# UTF3001 — Suppress NUnit2045 (Use Assert.Multiple) when Assert.Multiple is not available

Suppresses NUnit2045 ("Use Assert.Multiple") reported by NUnit.Analyzers when the referenced `nunit.framework` assembly does not define `Assert.Multiple`. The NUnit shipped with Unity Test Framework is based on NUnit 3.5, which predates `Assert.Multiple`, so the suggestion cannot be followed.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | NUnit2045  |
| CodeFix    | False      |

Justification: "Assert.Multiple is not available in the NUnit shipped with Unity Test Framework."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

## Motivation

`Assert.Multiple` was introduced in NUnit 3.6 (release notes: "Adds support for Multiple Assert blocks"). Unity Test Framework depends on `com.unity.ext.nunit`, a custom build of NUnit 3.5; the `nunit.framework.dll` shipped in `com.unity.ext.nunit` 2.0.5 contains no `Multiple` symbol on `Assert`.

NUnit2045 reports two or more consecutive, independent `Assert.That` calls and suggests wrapping them in `Assert.Multiple`. NUnit.Analyzers 3.9.0 (`UseAssertMultipleAnalyzer`) does not check whether the referenced `nunit.framework` defines `Assert.Multiple` before reporting, so in a Unity project every such sequence is reported. Applying the accompanying code fix (`UseAssertMultipleCodeFix`) produces code that does not compile in Unity: CS0117 "'Assert' does not contain a definition for 'Multiple'". The diagnostic is therefore noise, and its code fix is a trap.

Without this suppressor, every Unity project that installs NUnit.Analyzers has to disable NUnit2045 by hand in `.editorconfig` or `.globalconfig`. This suppressor removes that manual step and keeps the rule active for projects whose NUnit does define `Assert.Multiple`.

## Suppressed

```csharp
using NUnit.Framework;
using UnityEngine;

public class MyTest
{
    [Test]
    public void TwoIndependentAssertions()
    {
        var actual = new Vector2Int(1, 2);
        Assert.That(actual.x, Is.EqualTo(1));   // NUnit2045 reported by NUnit.Analyzers, suppressed by UTF3001
        Assert.That(actual.y, Is.EqualTo(2));
    }
}
```

## Not compilable in Unity Test Framework

The code that NUnit2045 and its code fix suggest:

```csharp
using NUnit.Framework;
using UnityEngine;

public class MyTest
{
    [Test]
    public void TwoIndependentAssertions()
    {
        var actual = new Vector2Int(1, 2);
        Assert.Multiple(() =>   // CS0117: 'Assert' does not contain a definition for 'Multiple'
        {
            Assert.That(actual.x, Is.EqualTo(1));
            Assert.That(actual.y, Is.EqualTo(2));
        });
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `NUnit.Framework.Assert` and suppresses NUnit2045 only when that type has no member named `Multiple`. A project that references a `nunit.framework` defining `Assert.Multiple` (a newer `com.unity.ext.nunit`, or a NuGet-installed NUnit) keeps receiving NUnit2045. Suppressing unconditionally is simpler but would hide a valid suggestion in that case.
- Every NUnit2045 report in the compilation is suppressed when the condition holds; the suppressor does not re-examine the assertions. NUnit2045 only inspects sequences of `Assert.That` calls, and none of them can be rewritten with `Assert.Multiple` when the member does not exist.
- The suppressor has no effect when NUnit.Analyzers is not installed, because there is no NUnit2045 to suppress.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against NUnit.Analyzers 3.9.0, `com.unity.ext.nunit` 2.0.5, and the NUnit 3.6 release notes.
- The test does not run the real NUnit.Analyzers: its `IsAssert` check requires `Assert` to live in an assembly named `nunit.framework`, and the test dummies are compiled into the test assembly. A test-only stub reports NUnit2045 at each `Assert` call instead.

To see NUnit2045 again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3001
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3001" Action="None" />
</Rules>
```
