# UTF2005 — DelayedConstraint is not supported

Detects any call to `Constraint.After` (`Is.True.After(500)`, `Is.EqualTo(1).After(500, 50)`) and any `new DelayedConstraint(...)`. `DelayedConstraint` waits with `Thread.Sleep` on the calling thread. Unity Test Framework runs tests on the main thread, so nothing that is driven by the main thread can change while it waits, and a condition driven by the main thread never becomes true.

| Item     | Value     |
|----------|-----------|
| Category | Assertion |
| Enabled  | True      |
| Severity | Error     |
| CodeFix  | False     |

Message: "DelayedConstraint is not supported. Wait for the condition in a coroutine-style or 'async Task' test method and assert afterwards."

The diagnostic is reported at the `After` invocation or at the `DelayedConstraint` object creation.

Severity is Error because the assertion cannot pass when the condition is driven by the main thread, which is the case for everything that happens in a Unity frame (`Update`, coroutines, animation, physics, `async` continuations posted to `UnitySynchronizationContext`), and every run stalls the Editor for the full delay before failing. At Warning or below, the test would be run and would fail after a bounded but pointless wait.

## Motivation

`DelayedConstraint` is NUnit's way to assert on a condition that becomes true later: `After(delayInMilliseconds)` sleeps once and checks, and `After(delayInMilliseconds, pollingInterval)` re-checks at the polling interval until the delay expires. Both are implemented with `Thread.Sleep` on the calling thread in every `ApplyTo` overload of `DelayedConstraint`.

In Unity that calling thread is the main thread. While it sleeps, no frame advances: `Update` and `FixedUpdate` are not called, no coroutine steps, no `await` continuation posted to `UnitySynchronizationContext` runs, and no Unity API result arrives. Each poll therefore reads exactly the same state as the previous one, and the final check after the delay reads the same state as the first. A test written as `Assert.That(() => player.IsGrounded, Is.True.After(1000, 100))` fails after one second, however long the fall would take in real time.

A condition changed from a thread other than the main thread (for example, a flag set by `Task.Run`) does become true during the sleep, so the assertion can pass in that case. The analyzer cannot tell the two apart, and even in that case the Editor is stalled for the whole delay, so the rule reports every use.

The delegate overload additionally routes an async delegate through `AsyncInvocationRegion.WaitForPendingOperationsToComplete`, which waits for the returned `Task` synchronously on the main thread; that is the freeze described in UTF2001 and UTF2003, and UTF2003 reports such an actual value independently.

The intended way to wait for a condition in Unity Test Framework is to yield or await in the test method itself, so that the Editor keeps running frames: `yield return new WaitForSeconds(...)` in a coroutine-style test method, or `await Task.Delay(...)` in an `async Task` test method (see [Async tests](https://docs.unity3d.com/Manual/test-framework/reference-async-tests.html)).

Verified against the upstream NUnit 3.5 source of `DelayedConstraint` and `Constraint.After`, which `com.unity.ext.nunit` 2.0.5 is based on. The `nunit.framework.dll` shipped in `com.unity.ext.nunit` 2.0.5 contains the symbols `DelayedConstraint`, `After`, and `Sleep`; it does not contain the `Seconds`, `MilliSeconds`, and `PollEvery` modifiers added to NUnit later, so `After(int)` and `After(int, int)` are the only forms available.

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers treats `DelayedConstraint` as a supported API, because on a regular .NET test host `Thread.Sleep` blocks only a worker thread while the code under test keeps running on its own threads. Verified with NUnit.Analyzers 3.9.0: no rule reports a call to `After`; its only knowledge of `DelayedConstraint` is a helper that recognizes the type so that the type-compatibility rules can see through the wrapper.

## Bad

```csharp
using NUnit.Framework;
using NUnit.Framework.Constraints;

public class MyTest
{
    private bool _flag;

    [Test]
    public void SleepsThenFails()
    {
        StartFadeOut();   // completes over several frames
        Assert.That(() => _flag, Is.True.After(1000, 100));   // UTF2005; no frame advances during the sleep, the flag never changes
    }

    [Test]
    public void SingleCheck()
    {
        StartFadeOut();
        Assert.That(() => _flag, Is.True.After(1000));   // UTF2005; sleeps once, then checks the same state
    }

    [Test]
    public void ExplicitConstruction()
    {
        StartFadeOut();
        Assert.That(() => _flag, new DelayedConstraint(new TrueConstraint(), 1000));   // UTF2005
    }

    private void StartFadeOut()
    {
        // Sets _flag from a coroutine or Update several frames later
    }
}
```

## Good

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

public class MyTest
{
    private bool _flag;

    [UnityTest]
    public IEnumerator WaitsInCoroutine()
    {
        StartFadeOut();
        yield return new WaitForSeconds(1f);   // frames advance while waiting
        Assert.That(_flag, Is.True);
    }

    [Test]
    public async Task WaitsInAsync()
    {
        StartFadeOut();
        await Task.Delay(1000);   // the continuation is posted to the main thread, frames advance while waiting
        Assert.That(_flag, Is.True);
    }

    private void StartFadeOut()
    {
        // Sets _flag from a coroutine or Update several frames later
    }
}
```

## Notes

- Both overloads of `Constraint.After` are reported. `After` is declared on `NUnit.Framework.Constraints.Constraint` and is not virtual, so a call on any constraint type, including a custom constraint, resolves to the same symbol and is detected.
- The diagnostic is reported where the `DelayedConstraint` is created, so a constraint held in a local variable, field, or parameter and passed to `Assert.That` later is still reported at its creation site. No use-site tracking is needed.
- A subclass of `DelayedConstraint` is not detected; the object-creation check compares the exact type. A helper method in user code that returns a `DelayedConstraint` is reported inside the helper, not at its callers.
- Passing a plain value rather than a delegate (`Assert.That(_flag, Is.True.After(1000))`) captures the value once before the wait and is pointless even in plain NUnit. It is reported the same way.
- The rule is independent of UTF2003 and UTF2004. `Assert.That(async () => await GetAsync(), Is.True.After(100))` is reported by both UTF2003 (at the actual value) and UTF2005 (at `After`), and `Assert.That(() => dict.Remove(1), Is.Not.AllocatingGCMemory().After(10))` by both UTF2004 and UTF2005.
- `nameof(Constraint.After)` and a method group that is not invoked are not reported.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF2005.severity = warning
```
