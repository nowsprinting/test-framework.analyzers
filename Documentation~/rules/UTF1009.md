# UTF1009 — Only IEnumerator is supported as the return type of methods with the UnitySetUp, UnityTearDown, UnityOneTimeSetUp, and UnityOneTimeTearDown attributes

Detects a method marked with `UnitySetUpAttribute`, `UnityTearDownAttribute`, `UnityOneTimeSetUpAttribute`, or `UnityOneTimeTearDownAttribute` whose return type is not `System.Collections.IEnumerator`, such as `IEnumerator<T>`, `IEnumerable`, `Task`, or `void`. Unity Test Framework does not recognize such a method as a setup or teardown method, so it never runs, and the tests run without it and report no error.

| Item     | Value     |
|----------|-----------|
| Category | Structure |
| Enabled  | True      |
| Severity | Error     |
| CodeFix  | False     |

Message: "'{0}' is not supported as the return type of a method marked with '{1}': the method never runs. Return 'IEnumerator' instead."

`{0}` is the declared return type, e.g. `IEnumerator<object>`. `{1}` is the type name of the attribute that marks the method, e.g. `UnitySetUpAttribute`.

Severity is Error because no test in the fixture can be trusted: every test runs without the setup, and the state that the teardown should clean up leaks into the following tests. Unity Test Framework reports nothing, so a test may pass against the wrong state, and a failure in a later test points away from the cause.

## Motivation

The four attributes are plain marker classes derived from `NUnitAttribute`; they do not validate the method they are applied to. Unity Test Framework looks them up when it builds the commands that run a test: `EnumerableSetUpTearDownCommand` collects `[UnitySetUp]` and `[UnityTearDown]` methods, and `EnumerableOneTimeSetUpTearDownCommand` collects `[UnityOneTimeSetUp]` and `[UnityOneTimeTearDown]` methods. Both pass `typeof(IEnumerator)` as the only accepted return type to `BeforeAfterTestCommandBase.GetMethodsWithAttributeFromFixture`, which keeps only the methods whose return type is equal to it (`returnTypes.Any(type => type == method.ReturnType)`). A method with any other return type is dropped without a message. Unlike a `[UnityTest]` method with the wrong return type (see [UTF1008](UTF1008.md)), nothing marks the test as not runnable, so the Test Runner shows no sign of the mistake. Verified against the source of Unity Test Framework 1.3.4 and 1.6.0 (and 1.1.33 for `[UnitySetUp]` and `[UnityTearDown]`).

The check compares types for equality, not for assignability. `IEnumerator<T>` implements `IEnumerator`, and an iterator method can return any of `IEnumerator`, `IEnumerator<T>`, `IEnumerable`, or `IEnumerable<T>`, so these compile without a warning and look correct. Unity Test Framework ignores all of them except `IEnumerator`.

An `async Task` method with `[UnitySetUp]` or `[UnityTearDown]` is ignored the same way. Apply `[SetUp]` or `[TearDown]`, not `[UnitySetUp]` or `[UnityTearDown]`, to an `async Task` setup or teardown method (see [UTF4007](UTF4007.md)). There is no async counterpart for `[UnityOneTimeSetUp]` and `[UnityOneTimeTearDown]`, because `[OneTimeSetUp]` and `[OneTimeTearDown]` do not support async methods (see [UTF1004](UTF1004.md)).

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers has no rule about these methods; `UnitySetUpAttribute`, `UnityTearDownAttribute`, `UnityOneTimeSetUpAttribute`, and `UnityOneTimeTearDownAttribute` are Unity Test Framework extensions, and NUnit.Analyzers inspects only NUnit's own `SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, and `OneTimeTearDownAttribute`. Verified with NUnit.Analyzers 3.9.0.

## Bad

```csharp
using System.Collections;
using System.Collections.Generic;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnitySetUp]
    public IEnumerator<object> SetUp()   // UTF1009; never runs
    {
        yield return null;
    }

    [UnityTearDown]
    public IEnumerable TearDown()   // UTF1009; never runs
    {
        yield return null;
    }

    [UnityOneTimeSetUp]
    public async Task OneTimeSetUp()   // UTF1009; never runs
    {
        await Task.Yield();
    }

    [UnityOneTimeTearDown]
    public void OneTimeTearDown()   // UTF1009; never runs
    {
    }

    [Test]
    public void MyTestMethod()
    {
        Assert.That(true, Is.True);
    }
}
```

## Good

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
    }

    [TearDown]
    public async Task TearDown()   // Apply [TearDown] to an async Task teardown method
    {
        await Task.Yield();
    }

    [UnityOneTimeSetUp]
    public IEnumerator OneTimeSetUp()
    {
        yield return null;
    }

    [OneTimeTearDown]
    public void OneTimeTearDown()   // Apply [OneTimeTearDown] to a synchronous teardown method
    {
    }

    [Test]
    public void MyTestMethod()
    {
        Assert.That(true, Is.True);
    }
}
```

## Notes

- The rule matches any method marked with one of the four attributes whose return type is not exactly `System.Collections.IEnumerator`, the same condition that Unity Test Framework uses. The diagnostic is reported once per method, at the return type, even when more than one of the attributes is applied to the method. In that case, `{1}` is the first of them in declaration order.
- Only the four attributes themselves are matched; attributes derived from them are not detected. Attributes inherited from an overridden base method are not inspected either; the base declaration has the same return type and is reported instead.
- Other attributes applied to the method, such as `[SetUp]` or `[TearDown]`, do not affect the diagnostic.
- `UnityOneTimeSetUpAttribute` and `UnityOneTimeTearDownAttribute` were added in Unity Test Framework 1.5.0. With an earlier version, the types do not exist and only `UnitySetUpAttribute` and `UnityTearDownAttribute` are inspected.
- An async `[SetUp]` or `[TearDown]` method whose return type is not `Task` is out of scope; UTF1007 reports it.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF1009.severity = warning
```
