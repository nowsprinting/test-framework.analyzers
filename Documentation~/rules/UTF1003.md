# UTF1003 — Pairwise, Sequential, and Combinatorial attributes are not supported on coroutine-style test methods

Detects `PairwiseAttribute`, `SequentialAttribute`, or `CombinatorialAttribute` applied to a test method whose return type is `System.Collections.IEnumerator` (a coroutine-style test method).

| Item     | Value     |
|----------|-----------|
| Category | Structure |
| Enabled  | True      |
| Severity | Error     |
| CodeFix  | False     |

Message: "'{0}' is not supported on coroutine-style test methods: its test cases never run. Use an 'async Task' test method instead."

`{0}` is the type name of the offending attribute, `PairwiseAttribute`, `SequentialAttribute`, or `CombinatorialAttribute`.

Severity is Error because the test cases built by the attribute cannot run: NUnit marks them as not runnable when they are loaded, so they are reported as failures without exercising any of the code under test.

## Motivation

`PairwiseAttribute`, `SequentialAttribute`, and `CombinatorialAttribute` are NUnit combining strategy attributes: each is an `ITestBuilder` that builds the test cases from the values supplied to the parameters. NUnit's `DefaultTestCaseBuilder` runs every `ITestBuilder` attribute on the method, and each builds its own set of test cases.

`UnityTestAttribute` is itself a combining strategy attribute (always combinatorial). It builds `IEnumerator` test cases with a workaround that makes NUnit accept the non-void return type. The other combining strategy attributes have no such workaround, so every test case they build on an `IEnumerator` method is rejected with the message "Method has non-void return value, but no result is expected" and its run state set to `NotRunnable`. The result depends on whether `[UnityTest]` is also applied:

- With `UnityTestAttribute`: two sets of test cases are generated. The cases from `UnityTestAttribute` run with the combinatorial strategy, ignoring the requested strategy, and the cases from the other attribute appear as duplicate entries that always fail. Verified with Unity Test Framework 1.6.0.
- Without `UnityTestAttribute`: every test case fails as not runnable, and the coroutine body never executes.

The [official documentation](https://docs.unity3d.com/Manual/test-framework/reference-tests-parameterized.html) states that Unity tests only support `ValueSourceAttribute`, which implies the combinatorial strategy.

Unity Test Framework supports `async Task` test methods marked with `[Test]`, and the combining strategy attributes work on them. Rewriting the coroutine as an `async Task` method (or a synchronous `void` method) gives pairwise and sequential test cases without workarounds.

### Why NUnit1007 cannot be used instead

NUnit.Analyzers reports NUnit1007 ("The method has non-void return type, but no result is expected in ExpectedResult") only for `TestCaseAttribute`. It does not inspect combining strategy attributes, so this defect is never reported.

## Bad

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnityTest]
    [Pairwise]   // UTF1003; the Pairwise cases are not runnable, the UnityTest cases run combinatorially
    public IEnumerator MyPairwiseCoroutineTest([Values(1, 2)] int a, [Values(3, 4)] int b)
    {
        yield return null;
        Assert.That(a + b, Is.GreaterThan(0));
    }

    [Sequential]   // UTF1003; not runnable, the coroutine body never executes
    public IEnumerator MySequentialCoroutineTest([Values(1, 2)] int a, [Values(3, 4)] int b)
    {
        yield return null;
        Assert.That(a + b, Is.GreaterThan(0));
    }
}
```

## Good

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [Test]
    [Pairwise]
    public async Task MyPairwiseAsyncTest([Values(1, 2)] int a, [Values(3, 4)] int b)
    {
        await Task.Yield();
        Assert.That(a + b, Is.GreaterThan(0));
    }

    [Test]
    [Sequential]
    public async Task MySequentialAsyncTest([Values(1, 2)] int a, [Values(3, 4)] int b)
    {
        await Task.Yield();
        Assert.That(a + b, Is.GreaterThan(0));
    }

    [UnityTest]   // combinatorial; ValueSource, Values, and Range work without a combining strategy attribute
    public IEnumerator MyCoroutineTest([Values(1, 2)] int a, [Values(3, 4)] int b)
    {
        yield return null;
        Assert.That(a + b, Is.GreaterThan(0));
    }
}
```

## Notes

- The rule matches only when the return type is exactly `System.Collections.IEnumerator`, the same condition Unity Test Framework uses to decide to run a method as a coroutine. `IEnumerator<T>` and `IEnumerable` are not matched.
- Whether `[UnityTest]` is also applied does not affect the diagnostic.
- `CombinatorialAttribute` is matched even though `UnityTestAttribute` already uses the combinatorial strategy, because the explicit attribute still generates the not-runnable duplicate cases.
- The diagnostic is reported at each offending attribute.
- Only `PairwiseAttribute`, `SequentialAttribute`, and `CombinatorialAttribute` themselves are matched; other `CombiningStrategyAttribute` subclasses, including user-defined ones, are not detected.
- `MaxTimeAttribute` and `ParametrizedIgnoreAttribute` are out of scope. `MaxTimeAttribute` has been supported on `UnityTest` methods since Unity Test Framework 1.4.5, which covers every version this package supports. `ParametrizedIgnoreAttribute` handles `IEnumerator` methods itself; verified with Unity Test Framework 1.6.0.
- Method-level parameterized attributes (`TestCaseAttribute`, `TestCaseSourceAttribute`) are covered by UTF1001.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF1003.severity = warning
```
