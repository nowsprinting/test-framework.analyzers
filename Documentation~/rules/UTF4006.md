# UTF4006 — Async Task test methods are recommended over coroutine-style test methods with the UnityTest attribute

Detects a coroutine-style test method (a test method whose return type is `System.Collections.IEnumerator`) whose every `yield return` yields `null` or a Unity yield instruction, so that the method can be written as an `async Task` test method with no other change. A coroutine-style test method that yields anything else, e.g. an `IEnumerator` returned by the code under test, is not reported.

| Item     | Value     |
|----------|-----------|
| Category | Style     |
| Enabled  | True      |
| Severity | Warning   |
| CodeFix  | False     |

Message: "'{0}' is a coroutine-style test method that yields only Unity yield instructions: it cannot use TestCase attributes or catch an exception across a wait. Use an 'async Task' test method instead."

`{0}` is the name of the test method.

The diagnostic is reported once per method, at the method identifier.

Severity is Warning because the test runs and passes as written; nothing has to be stopped before the run. The rule reports a design choice that forgoes parameterized test cases and exception handling across a wait. In a project with many coroutine-style tests written before `async Task` test methods were supported, every one of them is reported at once; lower the severity to `suggestion` there (see Notes) and raise it back when the migration is done.

## Motivation

Unity Test Framework supports two ways to write a test that spans frames: a coroutine-style test method with `[UnityTest]`, and an `async Task` test method with `[Test]`. Both run in Edit Mode and Play Mode; the [official documentation](https://docs.unity3d.com/Manual/test-framework/reference-async-tests.html) states that async code runs on the main thread and the framework awaits it "by checking if the task is done on each update for Play mode or on each EditorApplication.update outside Play mode". Where both forms express the same test, the `async Task` form has two advantages that the coroutine-style form cannot have:

- Method-level parameterized attributes work on it. `TestCase` and `TestCaseSource` (UTF1001) and `Pairwise`, `Sequential`, and `Combinatorial` (UTF1003) are not supported on coroutine-style test methods, because NUnit rejects a non-void return type when it builds the test cases. They are supported on `async Task` test methods.
- An exception thrown across a wait can be caught. C# does not allow `yield return` inside a `try` block that has a `catch` clause (compiler error CS1626), so a coroutine-style test cannot wait inside a `try` and assert on the exception that the code under test throws some frames later. `await` inside a `try` block with a `catch` clause is allowed, and the official documentation shows this `try`/`catch` pattern as the way to assert an exception in an async test.

Every yield instruction that Unity ships has an `await` counterpart, so a test that yields only those converts mechanically:

| `yield return`                                   | `await`                                                                 |
|--------------------------------------------------|-------------------------------------------------------------------------|
| `null`                                           | `Awaitable.NextFrameAsync()`, `UniTask.NextFrame()`, or `Task.Yield()`  |
| `new WaitForSeconds(s)`, `new WaitForSecondsRealtime(s)` | `Awaitable.WaitForSecondsAsync(s)`, `UniTask.WaitForSeconds(s)`, or `Task.Delay(ms)` |
| `new WaitForEndOfFrame()`                        | `Awaitable.EndOfFrameAsync()`                                           |
| `new WaitForFixedUpdate()`                       | `Awaitable.FixedUpdateAsync()`                                          |
| `new WaitUntil(p)`, `new WaitWhile(p)`           | `UniTask.WaitUntil(p)`, `UniTask.WaitWhile(p)`, or a `while` loop that awaits a frame |
| an `AsyncOperation`                              | `Awaitable.FromAsyncOperation(op)` or `op.ToUniTask()`                  |

`Awaitable.NextFrameAsync`, `WaitForSecondsAsync`, `EndOfFrameAsync`, `FixedUpdateAsync`, and `FromAsyncOperation` are verified against the Unity 6000.4 Script Reference. In a Unity version without `UnityEngine.Awaitable`, UniTask (verified against UniTask 2.5.11) or `System.Threading.Tasks.Task` provides the same waits.

A coroutine-style test method that yields anything else is not reported, because the conversion is not mechanical there and the coroutine may be the point of the test:

- An `IEnumerator` returned by the code under test (`yield return player.FadeOut()`) or a `Coroutine` (`yield return StartCoroutine(...)`): the test target is a coroutine, and driving it from an `async Task` test needs an adapter.
- An `IEnumerator` returned by another package, e.g. `Measure.Frames().Run()` of the Unity Performance Testing package (`FramesMeasurement.Run()` returns `IEnumerator`, verified against com.unity.test-framework.performance 3.5.0), which measures the frames the test yields.
- An Edit Mode instruction such as `EnterPlayMode`, `ExitPlayMode`, `RecompileScripts`, or `WaitForDomainReload`: these implement `IEditModeTestYieldInstruction`, not `YieldInstruction`, and have no async counterpart.
- A `CustomYieldInstruction` declared outside the `UnityEngine` namespace: it is an API of the code under test, like an `IEnumerator`.

The exemption is by shape, not by API name: a yielded value is recognized as convertible only when it is the `null` literal or its type derives from `UnityEngine.YieldInstruction` or `UnityEngine.CustomYieldInstruction` and is declared in the `UnityEngine` namespace or a namespace under it, excluding `UnityEngine.Coroutine`. Everything the rule does not recognize exempts the method, so a new coroutine-based API in the code under test or in a package is exempt without a change to the analyzer.

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers has no rule about `IEnumerator` test methods; the return type is a Unity Test Framework extension. Verified with NUnit.Analyzers 3.9.0.

## Bad

```csharp
using System.Collections;
using NUnit.Framework;
using Unity.PerformanceTesting;
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.TestTools;

public class MyTest
{
    private bool _faded;

    [UnityTest]
    public IEnumerator YieldNull()   // UTF4006
    {
        StartFadeOut();
        yield return null;
        Assert.That(_faded, Is.True);
    }

    [UnityTest]
    public IEnumerator YieldWaitUntil()   // UTF4006
    {
        StartFadeOut();
        yield return new WaitUntil(() => _faded);
        Assert.That(_faded, Is.True);
    }

    [UnityTest]
    public IEnumerator YieldAsyncOperation()   // UTF4006; AsyncOperation derives from YieldInstruction
    {
        yield return SceneManager.LoadSceneAsync("Main");
        Assert.That(SceneManager.GetActiveScene().name, Is.EqualTo("Main"));
    }

    [UnityTest]
    public IEnumerator YieldFixtureHelper()   // UTF4006; the helper is an iterator declared in the fixture and yields only null
    {
        StartFadeOut();
        yield return WaitForFade();
        Assert.That(_faded, Is.True);
    }

    [UnityTest]
    [Performance]
    public IEnumerator MeasureFramesScope()   // UTF4006; Measure.Frames().Scope() is IDisposable and works in an async test
    {
        using (Measure.Frames().Scope())
        {
            yield return null;
        }
    }

    [UnityTest]
    public IEnumerator NoYieldReturn()   // UTF4006; a plain void test method is also fine
    {
        Assert.That(_faded, Is.False);
        yield break;
    }

    private IEnumerator WaitForFade()
    {
        while (!_faded)
        {
            yield return null;
        }
    }

    private void StartFadeOut()
    {
        // Sets _faded from a coroutine or Update several frames later
    }
}
```

## Good

```csharp
using System;
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using Unity.PerformanceTesting;
using UnityEngine;
using UnityEngine.TestTools;

public class MyTest
{
    private bool _faded;

    [Test]
    public async Task AwaitNextFrame()
    {
        StartFadeOut();
        await Awaitable.NextFrameAsync();
        Assert.That(_faded, Is.True);
    }

    [Test]
    public async Task CatchExceptionAcrossWait()   // not possible with yield return
    {
        var caught = false;
        try
        {
            await FadeOutAsync();
        }
        catch (InvalidOperationException)
        {
            caught = true;
        }

        Assert.That(caught, Is.True);
    }

    [UnityTest]
    public IEnumerator YieldCoroutineUnderTest()   // the test target is a coroutine
    {
        var player = new GameObject().AddComponent<FadePlayer>();
        yield return player.FadeOut();
        Assert.That(player.Faded, Is.True);
    }

    [UnityTest]
    public IEnumerator YieldStartCoroutine()   // Coroutine is excluded
    {
        var player = new GameObject().AddComponent<FadePlayer>();
        yield return player.StartCoroutine(player.FadeOut());
        Assert.That(player.Faded, Is.True);
    }

    [UnityTest]
    [Performance]
    public IEnumerator MeasureFrames()   // Measure.Frames().Run() returns IEnumerator
    {
        yield return Measure.Frames().Run();
    }

    [UnityTest]
    public IEnumerator YieldCustomInstructionUnderTest()   // CustomYieldInstruction declared outside Unity's assemblies
    {
        yield return new WaitForFadePlayer();
    }

    [UnityTest]
    public IEnumerator YieldEnterPlayMode()   // Edit Mode instruction, no async counterpart
    {
        yield return new EnterPlayMode();
        yield return new ExitPlayMode();
    }

    private async Task FadeOutAsync()
    {
        await Awaitable.NextFrameAsync();
        throw new InvalidOperationException();
    }

    private void StartFadeOut()
    {
        // Sets _faded from a coroutine or Update several frames later
    }
}
```

## Notes

- A test method is recognized the way NUnit builds tests, as in UTF4001: a method with an attribute implementing `ITestBuilder` or `ISimpleTestBuilder` (`[Test]`, `[UnityTest]`, `[TestCase]`, and user-defined builders) whose return type is `System.Collections.IEnumerator`. `[UnitySetUp]`, `[UnityTearDown]`, `[UnityOneTimeSetUp]`, and `[UnityOneTimeTearDown]` methods are not reported.
- A yielded value is recognized by the static type of the `yield return` operand, so a yield instruction cached in a field or a local (`yield return _oneFrame;` with `WaitForEndOfFrame _oneFrame`) counts as convertible, and an operand typed `object` or `IEnumerator` exempts the method even when it holds a `WaitForSeconds` at run time.
- A method with no `yield return` at all is reported: nothing in it needs a coroutine. A `void` test method with `[Test]` is as good a replacement as an `async Task` one.
- Helpers are followed only through `yield return` operands that are direct invocations (`yield return WaitForFade();`), only when the helper is an iterator (its body contains a `yield` statement) declared in the test method's containing type or one of its base types, and only two levels deep, with the same depth limit as UTF4001, UTF4003, and UTF4004. The walk is narrower than in those rules on purpose: a coroutine on any other type, including a test-only `MonoBehaviour` in the test assembly, is the code under test as far as this rule is concerned. Unlike those rules, an operand the walk cannot see through (a method on another type, a method in another assembly, a helper at depth 3, an `IEnumerator` method that is not an iterator, an `IEnumerator` held in a variable, a lambda) counts as not convertible and exempts the test method, because the report requires every yield to be convertible. Extracting a helper into the fixture does not exempt the test; an `IEnumerator` produced by the code under test does.
- A coroutine-style test method that is not an iterator (`return player.FadeOut();`) is not reported: it hands over an enumerator built elsewhere, and the rule does not see through it.
- A `yield return` inside a lambda or local function declared in the test method belongs to that lambda, not to the test method, and is not inspected.
- The `[Performance]` attribute is not an exemption. A performance test that yields `Measure.Frames().Run()` is exempt because the operand is an `IEnumerator`; one that yields only `null` inside `Measure.Frames().Scope()` or `Measure.Scope()` is reported, because both scopes are `IDisposable` and work in an `async Task` test method.
- `UnityEngine.Coroutine` derives from `YieldInstruction` but is excluded: the coroutine behind it is the test target. `UnityEngine.WWW` derives from `YieldInstruction` and is obsolete; it is treated like any other Unity yield instruction.
- `async Task` test methods have limitations of their own that a migrated test must respect: `Assert.ThrowsAsync` (UTF2001), `Task<TResult>` return types (UTF1002), and attributes implementing `ICommandWrapper` (UTF1005, which applies to coroutine-style test methods as well).
- Where a coroutine-style test is kept by choice, suppress the diagnostic at that method with `#pragma warning disable UTF4006`.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF4006.severity = suggestion
```
