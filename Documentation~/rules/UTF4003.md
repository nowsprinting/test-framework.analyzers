# UTF4003 — Waiting for a condition without yielding or awaiting does not advance frames

Detects a test, setup, or teardown method that waits without returning control to the test runner: a `while` or `do` loop whose body does no work (empty, or only calls to `Thread.Sleep`, `Thread.Yield`, `Thread.SpinWait`, or `SpinWait.SpinOnce`), and any call to `SpinWait.SpinUntil`. Unity Test Framework runs tests on the main thread, so nothing that is driven by the main thread can change while such a wait spins, and a condition driven by the main thread never becomes true. The `Timeout` attribute cannot end the test either, because the elapsed time is checked only when the test yields or returns.

| Item     | Value     |
|----------|-----------|
| Category | Style     |
| Enabled  | True      |
| Severity | Error     |
| CodeFix  | False     |

Message: "'{0}' waits for a condition without yielding or awaiting: the Editor freezes and a Timeout attribute cannot end the test. Yield or await while waiting instead."

`{0}` is the construct that waits: `while` or `do` for a loop, or `SpinWait.SpinUntil` for the invocation.

The diagnostic is reported at the `while` or `do` keyword of the loop, or at the `SpinWait.SpinUntil(...)` invocation, when the construct appears in a test method or in a `SetUp`, `TearDown`, `OneTimeSetUp`, `OneTimeTearDown`, `UnitySetUp`, `UnityTearDown`, `UnityOneTimeSetUp`, or `UnityOneTimeTearDown` method, including inside a lambda or local function declared in such a method. A method with several waits gets one diagnostic per wait.

Helpers are followed to a bounded depth, with the same walk as UTF4001. The test or hook method body is depth 0. An invocation that is the operand of `await` or `yield return` and resolves to a method with a body in the same compilation is walked at depth + 1, and a lambda or local function declared in the body being walked is walked at depth + 1 as well. Bodies at depth 3 and deeper are not walked. Unlike UTF4001, a wait found in a helper is reported at the loop or `SpinUntil` invocation inside the helper, not at the call site, because the fix is applied at the wait itself; a helper called from several places is reported once.

Severity is Error because the test must not be run: when the condition is driven by the main thread, the loop never ends and the Editor or the player has to be killed. At Warning or below, the test would be run, and unlike UTF4001 no `Timeout` attribute would rescue it.

## Motivation

A test that drives a state transition and then waits for it without yielding or awaiting is written as a busy loop or with the synchronous predicate-wait API of the BCL:

```csharp
while (!_grounded) { }
while (!_grounded) Thread.Sleep(10);
SpinWait.SpinUntil(() => _grounded);
```

In Unity the calling thread is the main thread. While it spins, no frame advances: `Update` and `FixedUpdate` are not called, no coroutine steps, no `await` continuation posted to `UnitySynchronizationContext` runs, and no Unity API result arrives. Each check of the condition therefore reads exactly the same state as the previous one, and a condition driven by the main thread never becomes true. This is the same mechanism described in UTF2005 for `DelayedConstraint`.

A condition changed from a thread other than the main thread (for example, a flag set by `Task.Run`) does become true during the spin, so such a loop can end. The analyzer cannot tell the two apart, and even in that case the Editor is stalled for the whole wait, so the rule reports every occurrence.

The `Timeout` attribute does not help. Unity Test Framework enforces the timeout cooperatively rather than by aborting a thread: `UnityTestMethodCommand` checks `HasTimedOut` after a synchronous test method returns, `EnumerableTestMethodCommand` and `TaskTestMethodCommand` check it after each `MoveNext` of the test enumerator, and `TimeoutCommand` checks it between the steps it yields to the runner (verified against Unity Test Framework 1.6.0 source). A test that never returns and never yields is never checked, so neither the 180-second default nor an explicit `Timeout` value ends it. UTF4001 and UTF4002 cover waits that do yield or await; this rule covers the ones that do not, and they are mutually exclusive by construction: UTF4001 and UTF4002 require a `yield return` or `await` in the loop body, and this rule requires a body that does no work.

The intended way to wait for a condition in Unity Test Framework is to yield or await in the test method itself, so that the Editor keeps running frames: `yield return null` or `yield return new WaitUntil(...)` in a coroutine-style test method, or `await UniTask.NextFrame()` or `await UniTask.WaitUntil(...)` in an `async Task` test method (see [Async tests](https://docs.unity3d.com/Manual/test-framework/reference-async-tests.html)). In a test method, apply a `Timeout` attribute as UTF4001 requires. In a setup or teardown method, a `Timeout` attribute is not enforced, so give the wait a time limit of its own as UTF4002 requires, e.g. a `WaitUntil` with a `TimeSpan` timeout.

### Why the loop is recognized by its body, not its condition

Whether a loop waits for a state transition is decided by what the body does, not by what the condition reads. A loop whose body does no work can end only when something outside the loop changes the condition, and on the main thread nothing does. A loop whose body does work (`while (queue.TryDequeue(out var item)) Process(item);`) drives its own condition and is a normal loop. Analyzing the condition would need data-flow analysis to prove that the body does not affect it, which is too expensive for an analyzer that runs on every keystroke and still could not see through a method call in the body.

"Does no work" is defined as: every statement in the body is an empty statement, or an expression statement that invokes `System.Threading.Thread.Sleep`, `Thread.Yield`, `Thread.SpinWait`, or `SpinWait.SpinOnce`. These are the BCL calls that only pass time (verified against .NET Standard 2.0: `Thread.Sleep(int)`, `Thread.Sleep(TimeSpan)`, `Thread.Yield()`, `Thread.SpinWait(int)`, `SpinWait.SpinOnce()`). The list is closed and does not grow with libraries or projects.

`SpinWait.SpinUntil` is the synchronous counterpart of `WaitUntil`: it spins on the calling thread until the predicate holds. All three overloads are reported (`SpinUntil(Func<bool>)`, `SpinUntil(Func<bool>, int millisecondsTimeout)`, and `SpinUntil(Func<bool>, TimeSpan timeout)`, verified against .NET Standard 2.0). The overloads with a timeout end by themselves, but the condition still never becomes true during the spin and the Editor is stalled for the whole timeout, so they are reported the same way, as UTF2005 reports every `After` overload.

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers has no rule about busy loops or `SpinWait.SpinUntil`. On a regular .NET test host a test is run on a worker thread and the code under test keeps running on its own threads, so a busy loop there does end and there is nothing for it to report. Verified with NUnit.Analyzers 3.9.0: the analyzer assembly contains no reference to `SpinUntil` or to a loop-shaped rule.

## Bad

```csharp
using System;
using System.Collections;
using System.Threading;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    private bool _grounded;

    [Test]
    public void EmptyLoop()
    {
        StartLanding();
        while (!_grounded) { }   // UTF4003; no frame advances, the flag never changes
        Assert.That(_grounded, Is.True);
    }

    [Test]
    public void SleepInLoop()
    {
        StartLanding();
        while (!_grounded)
        {
            Thread.Sleep(10);   // UTF4003; reported at 'while'
        }
        Assert.That(_grounded, Is.True);
    }

    [Test]
    public void DoLoop()
    {
        StartLanding();
        do { } while (!_grounded);   // UTF4003; reported at 'do'
        Assert.That(_grounded, Is.True);
    }

    [Test]
    public void SpinUntil()
    {
        StartLanding();
        SpinWait.SpinUntil(() => _grounded);   // UTF4003
        Assert.That(_grounded, Is.True);
    }

    [Test]
    public void SpinUntilWithTimeout()
    {
        StartLanding();
        var landed = SpinWait.SpinUntil(() => _grounded, 1000);   // UTF4003; stalls for one second, then returns false
        Assert.That(landed, Is.True);
    }

    [UnityTest]
    public IEnumerator BusyLoopInCoroutine()
    {
        StartLanding();
        while (!_grounded) { }   // UTF4003; a coroutine-style test method does not help when the loop never yields
        yield return null;
        Assert.That(_grounded, Is.True);
    }

    [Test]
    public async Task BusyLoopInAsync()
    {
        StartLanding();
        while (!_grounded) { }   // UTF4003; an 'async Task' test method does not help when the loop never awaits
        await Task.Yield();
        Assert.That(_grounded, Is.True);
    }

    [UnitySetUp]
    public IEnumerator BusyLoopInSetUp()
    {
        StartLanding();
        while (!_grounded) { }   // UTF4003; reported in hook methods too
        yield return null;
    }

    [Test]
    public void BusyLoopInLambda()
    {
        StartLanding();
        Action wait = () =>
        {
            while (!_grounded) { }   // UTF4003; reported at the loop inside the lambda (depth 1)
        };
        wait();
        Assert.That(_grounded, Is.True);
    }

    [UnityTest]
    public IEnumerator BusyLoopInHelper()
    {
        StartLanding();
        yield return WaitForLanding();   // not reported here; the loop inside the helper is reported (depth 1)
        Assert.That(_grounded, Is.True);
    }

    private IEnumerator WaitForLanding()
    {
        while (!_grounded) { }   // UTF4003; reported at the loop, once, however many callers the helper has
        yield break;
    }

    [Test]
    public void BusyLoopInLocalFunction()
    {
        StartLanding();
        Wait();
        Assert.That(_grounded, Is.True);

        void Wait()
        {
            while (!_grounded) { }   // UTF4003; reported at the loop inside the local function (depth 1)
        }
    }

    private void StartLanding()
    {
        // Sets _grounded from a coroutine or Update several frames later
    }
}
```

## Good

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
using System.Threading.Tasks;
using Cysharp.Threading.Tasks;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

public class MyTest
{
    private bool _grounded;
    private readonly Queue<int> _queue = new Queue<int>();

    [UnityTest]
    [Timeout(5000)]
    public IEnumerator YieldInLoop()
    {
        StartLanding();
        while (!_grounded)
        {
            yield return null;   // frames advance while waiting
        }
        Assert.That(_grounded, Is.True);
    }

    [UnityTest]
    [Timeout(5000)]
    public IEnumerator WaitUntilInCoroutine()
    {
        StartLanding();
        yield return new WaitUntil(() => _grounded);
        Assert.That(_grounded, Is.True);
    }

    [Test]
    [Timeout(5000)]
    public async Task AwaitInLoop()
    {
        StartLanding();
        while (!_grounded)
        {
            await UniTask.NextFrame();   // the continuation is posted to the main thread, frames advance while waiting
        }
        Assert.That(_grounded, Is.True);
    }

    [Test]
    [Timeout(5000)]
    public async Task UniTaskWaitUntilInAsync()
    {
        StartLanding();
        await UniTask.WaitUntil(() => _grounded);
        Assert.That(_grounded, Is.True);
    }

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        StartLanding();
        yield return new WaitUntil(() => _grounded, TimeSpan.FromSeconds(5), () => { }, WaitTimeoutMode.Realtime);   // frames advance, and the wait has a time limit of its own as UTF4002 requires
    }

    [Test]
    public void LoopThatDoesWork()   // the body drives the condition; not a wait
    {
        _queue.Enqueue(1);
        _queue.Enqueue(2);
        while (_queue.Count > 0)
        {
            Process(_queue.Dequeue());
        }
        Assert.That(_queue, Is.Empty);
    }

    private void Process(int item)
    {
    }

    private void StartLanding()
    {
        // Sets _grounded from a coroutine or Update several frames later
    }
}
```

## Notes

- A test method is recognized the way NUnit builds tests, as in UTF4001: a method with an attribute implementing `ITestBuilder` or `ISimpleTestBuilder` (`[Test]`, `[UnityTest]`, `[TestCase]`, and user-defined builders). A hook method is a method with `[SetUp]`, `[TearDown]`, `[OneTimeSetUp]`, `[OneTimeTearDown]`, `[UnitySetUp]`, `[UnityTearDown]`, `[UnityOneTimeSetUp]`, or `[UnityOneTimeTearDown]`, applied to the method itself or to a base declaration it overrides. A busy loop in any other method is not reported unless the method is reached through the walk.
- Unlike UTF4002, the return type of a hook method is not checked and `[OneTimeSetUp]` and `[OneTimeTearDown]` are included. UTF4002 needs a return type the framework runs as a coroutine or polls as a task, because the wait it reports happens between steps; a busy loop stalls the main thread whatever the framework does with the return value: an `async Task` `[SetUp]` runs synchronously up to its first `await`, a `Task`-returning `[UnitySetUp]` is skipped by the framework but its loop still spins if it is ever called, and a synchronous `[OneTimeSetUp]` is a natural place for one.
- A lambda or local function declared in a walked body is walked whether or not it is invoked, so a loop in a lambda that is stored but never called is still reported, and a loop at depth 3 (a lambda inside a lambda inside a lambda) is not. A local function is reported at its loop, not at its invocation, so it is reported once.
- Helpers are followed only through `await` and `yield return` operands (`yield return WaitForLanding();`), only when the helper has a body in the same compilation, and only two levels deep, with the same limits as UTF4001. A helper invoked as a plain statement (`WaitForLanding();`) is not seen through, because following every invocation would walk an arbitrary call graph on every keystroke; the busy loop inside it is reported only when the helper is itself a test or hook method.
- A busy loop in a helper declared in another file than the test or hook method that reaches it is reported at the loop, so the diagnostic belongs to a document that is not the one being analyzed. An IDE that analyzes open documents one at a time may show it only on build; the compiler reports it always.
- The condition of the loop is not analyzed. A loop bounded by real time (`while (stopwatch.ElapsedMilliseconds < 100) { }`) is reported: it ends, but no frame advances while it spins, and the same result is obtained with `yield return new WaitForSeconds(0.1f)` without stalling the Editor.
- A loop whose body does anything else is not reported, even when it is a wait in practice: `while (true) { if (_grounded) break; }`, `while (!_grounded) { count++; }`, and `while (!_grounded) Debug.Log("waiting");` are not seen. `for` and `foreach` loops are not reported either.
- A loop that yields or awaits in its body is never reported by this rule; UTF4001 reports it when the test method has no `Timeout` attribute, and UTF4002 reports it in a setup or teardown method when the wait has no time limit of its own.
- Blocking on a task or a synchronization primitive (`task.Wait()`, `task.Result`, `resetEvent.WaitOne()`) is not reported. Waiting on a `Task` is covered by UTF1002, UTF1004, UTF2001, UTF2002, and UTF2003 where an NUnit or UTF API does it, and the general case is reported by Microsoft.VisualStudio.Threading.Analyzers as VSTHRD002.
- A single `Thread.Sleep(...)` outside a loop is not reported. It stalls the Editor for a bounded time but waits for nothing.
- A busy loop that runs on a thread other than the main thread (for example, inside a lambda passed to `Task.Run`) is reported too; the analyzer cannot tell which thread runs the loop. Suppress the diagnostic at that site with `#pragma warning disable UTF4003` when the loop is intended.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF4003.severity = warning
```
