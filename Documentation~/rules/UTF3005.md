# UTF3005 — Suppress CA1707 (Identifiers should not contain underscores) on test methods

Suppresses CA1707 ("Identifiers should not contain underscores") reported by Microsoft.CodeAnalysis.NetAnalyzers on a method marked with an attribute that implements `NUnit.Framework.Interfaces.ITestBuilder` or `NUnit.Framework.Interfaces.ISimpleTestBuilder`. `TestAttribute`, `UnityTestAttribute`, `TestCaseAttribute`, and `TestCaseSourceAttribute` implement one of them, and so does every attribute derived from them.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | CA1707     |
| CodeFix    | False      |

Justification: "Method is a test method; underscores in its name separate the scenario and the expected result."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

## Motivation

CA1707 (`IdentifiersShouldNotContainUnderscoresAnalyzer`, member message "Remove the underscores from member name {0}") reports every namespace, type, member, and parameter whose name contains an underscore. Its descriptor is created with `RuleLevel.IdeHidden_BulkConfigurable`, which maps to `DefaultSeverity.Hidden` and `isEnabledByDefault: true` (`DiagnosticDescriptorHelper`); the rule documentation lists it as not enabled by default in .NET 10, and a project opts in by raising the severity in `.editorconfig` or `.globalconfig`. Hidden is not Error, so Roslyn hands the diagnostic to suppressors; the filter is on the descriptor's default severity, so a project that raises CA1707 to `warning` or `error` still gets the suppression. CA1707 has no code fix; the [rule documentation](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/quality-rules/ca1707) says "Remove all underscore characters from the name", and under "When to suppress warnings" it says: "Do not suppress warnings for production code. However, it's safe to suppress this warning for test code."

Test methods are named for the reader of a test report, not for a caller. The `Method_State_ExpectedResult` convention (and its variants) is the common way to name a test method after the scenario it covers and the result it expects; the underscores are the separators. Removing them collapses the name into a single camel-case run and makes the report harder to read, while nothing calls the method, so the naming-convention argument behind CA1707 (a common look for library consumers) does not apply. Yet CA1707 reports every such method, because test methods are public and the rule's default `api_surface` is the public surface.

NUnit.Analyzers has no suppressor for CA1707 (its suppressors are NUnit3001 through NUnit3004, verified in NUnit.Analyzers 3.9.0). Without this suppressor, a project either disables CA1707 for the whole test assembly with `dotnet_diagnostic.CA1707.severity = none`, which also silences it on fixture classes, fields, and helper methods where the rule is right, or annotates every test method with a `#pragma` or `[SuppressMessage]`.

### Why the criterion is the builder interface, not the four attribute types

The four attributes share no base class narrower than `NUnitAttribute`, which `SetUpAttribute`, `TearDownAttribute`, and every other NUnit attribute also derive from, so "derives from one of the four" would need a base-class walk against four named types, and it would still miss an attribute that makes a method a test without deriving from any of them. NUnit does not discover test methods by attribute type. `DefaultTestCaseBuilder.CanBuildFrom` in NUnit 3.5 (the NUnit shipped as `com.unity.ext.nunit` 2.0.5) is:

```csharp
public bool CanBuildFrom(IMethodInfo method)
{
    return method.IsDefined<ITestBuilder>(false)
        || method.IsDefined<ISimpleTestBuilder>(false);
}
```

A method is a test method exactly when one of its attributes implements `ITestBuilder` or `ISimpleTestBuilder`. The four attributes do (`TestAttribute : NUnitAttribute, ISimpleTestBuilder, IApplyToTest, IImplyFixture`; `TestCaseAttribute : NUnitAttribute, ITestBuilder, ITestCaseData, IImplyFixture`; `TestCaseSourceAttribute : NUnitAttribute, ITestBuilder, IImplyFixture` in NUnit 3.5; `UnityTestAttribute : CombiningStrategyAttribute, IImplyFixture, ISimpleTestBuilder, ITestBuilder, IApplyToTest` in Unity Test Framework 1.6.0). A class derived from any of them inherits the interfaces, so an unknown derived attribute is covered. NUnit.Analyzers recognizes test methods the same way (`AttributeDataExtensions.IsTestMethodAttribute` checks `AttributeClass.AllInterfaces` for the two interfaces, verified in 3.9.0), and so does UTF1005 in this package.

The set is therefore a superset of the four attributes listed above. `[Theory]`, and `[Combinatorial]`, `[Pairwise]`, or `[Sequential]` applied without `[Test]`, also mark a test method (`CombiningStrategyAttribute : NUnitAttribute, ITestBuilder, IApplyToTest` in NUnit 3.5, and NUnit runs such a method as a test), as does a user-defined attribute implementing either interface. Every method NUnit runs as a test is suppressed; no method NUnit does not run as a test is.

## Suppressed

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [Test]
    public void Add_TwoPositiveNumbers_ReturnsSum()   // CA1707 reported by Microsoft.CodeAnalysis.NetAnalyzers, suppressed by UTF3005
    {
    }

    [UnityTest]
    public IEnumerator LoadScene_SceneExists_IsLoadedAfterOneFrame()   // Suppressed by UTF3005
    {
        yield return null;
    }

    [TestCase(1)]
    [TestCase(2)]
    public void IsPositive_PositiveNumber_ReturnsTrue(int value)   // Suppressed by UTF3005
    {
    }

    [TestCaseSource(nameof(Cases))]
    public void IsPositive_FromSource_ReturnsTrue(int value)   // Suppressed by UTF3005
    {
    }

    private static readonly int[] Cases = { 1, 2 };
}
```

A user-defined attribute is recognized through the interface, whether it derives from one of the four attributes or implements the interface directly:

```csharp
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using NUnit.Framework.Internal;

public class MyTestAttribute : TestAttribute   // Inherits ISimpleTestBuilder from TestAttribute
{
}

public class MyTestBuilderAttribute : NUnitAttribute, ISimpleTestBuilder
{
    public TestMethod BuildFrom(IMethodInfo method, Test suite) => new TestMethod(method, suite);
}

public class CalculatorTest
{
    [MyTest]
    public void Add_TwoPositiveNumbers_ReturnsSum()   // Suppressed by UTF3005
    {
    }

    [MyTestBuilder]
    public void Add_TwoNegativeNumbers_ReturnsSum()   // Suppressed by UTF3005
    {
    }
}
```

## What CA1707 asks for instead

There is no code fix; the rule asks for a manual rename. The method still runs as a test, but the report no longer separates the scenario from the expected result:

```csharp
using NUnit.Framework;

public class MyTest
{
    [Test]
    public void AddTwoPositiveNumbersReturnsSum()
    {
    }
}
```

## Not suppressed

Only test methods are suppressed. CA1707 stays on fixture class names, fields, setup and teardown methods, parameters, and helper methods:

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class My_Test   // CA1707 (type) reported by Microsoft.CodeAnalysis.NetAnalyzers, not suppressed
{
    public const int Max_Count = 3;   // CA1707 (member) reported, not suppressed

    [SetUp]
    public void Set_Up()   // CA1707 (member) reported, not suppressed: SetUpAttribute implements neither interface
    {
    }

    [UnitySetUp]
    public IEnumerator Unity_SetUp()   // CA1707 (member) reported, not suppressed
    {
        yield return null;
    }

    [TestCase(3)]
    public void Add_TwoNumbers_ReturnsSum(int expected_value)   // Method suppressed; CA1707 (parameter) on expected_value reported, not suppressed
    {
    }

    public void Create_Fixture()   // CA1707 (member) reported, not suppressed
    {
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `NUnit.Framework.Interfaces.ITestBuilder` and `NUnit.Framework.Interfaces.ISimpleTestBuilder` independently and returns without suppressing only when neither exists in the compilation. Both exist in NUnit 3.5 (`com.unity.ext.nunit` 2.0.5), the baseline, so the condition is a guard against a compilation that does not reference NUnit at all rather than a version check. Interfaces are matched by symbol, not by name, so a user-defined interface named `ITestBuilder` in another namespace does not count. `UnityTestAttribute` is not required to exist: the justification does not depend on Unity Test Framework, and the check is the one NUnit itself uses.
- A CA1707 report is suppressed when the reported method is marked with an attribute whose class (`AttributeClass.AllInterfaces`) implements either interface. Only the method's own attributes are examined. CA1707 skips overrides (`!symbol.IsOverride`) and interface implementations (`!symbol.IsImplementationOfAnyInterfaceMember()`) before reporting, so the walk over overridden methods that UTF3004 performs for NUnit1028 has nothing to find here and is not performed.
- Only CA1707 reports whose location resolves to a method declaration are handled. CA1707 reports at `symbol.Locations[0]` through `CreateDiagnostic`, that is, at the method identifier, whose enclosing node is the method declaration. Reports on types, fields, properties, events, and namespaces resolve to other declaration nodes and are left alone. A report on a parameter of a test method resolves to the parameter node and is left alone as well: parameter names are not what the test report shows.
- Setup and teardown methods (`SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, `OneTimeTearDownAttribute`, and their Unity Test Framework counterparts) are not suppressed. They implement neither interface, they are not shown in a test report, and the request this rule answers names test methods only.
- Accessibility and return type are not examined. A method marked with a builder attribute is a test method by intent, and whether it is a valid one is a separate concern, as in UTF3004.
- Methods marked with `[Theory]`, or with `[Combinatorial]`, `[Pairwise]`, or `[Sequential]` alone, and methods marked with a user-defined attribute implementing either interface, are suppressed for the reason given under Motivation: NUnit runs them as tests.
- CA1707 is reported only when Microsoft.CodeAnalysis.NetAnalyzers is installed in the project as a Roslyn analyzer and CA1707 is raised above its default Hidden severity, so the suppressor has no effect otherwise.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against the Microsoft.CodeAnalysis.NetAnalyzers source (`IdentifiersShouldNotContainUnderscores.cs` and `DiagnosticDescriptorHelper.cs` on the main branch, read on 2026-09-07; 10.0.400 is the current stable release), the CA1707 rule documentation, NUnit.Analyzers 3.9.0 (`AttributeDataExtensions.IsTestMethodAttribute`; suppressors NUnit3001 to NUnit3004 only), `com.unity.ext.nunit` 2.0.5 (NUnit 3.5: `DefaultTestCaseBuilder.CanBuildFrom`, `TestAttribute`, `TestCaseAttribute`, `TestCaseSourceAttribute`, `CombiningStrategyAttribute`), and Unity Test Framework 1.6.0 (`UnityTestAttribute`).
- The test does not run the real Microsoft.CodeAnalysis.NetAnalyzers; a test-only stub (`CA1707StubAnalyzer`, default severity Hidden like the real rule, since Roslyn never passes an Error-by-default diagnostic to a suppressor) reports CA1707 at the identifier of every ordinary method whose name contains an underscore, as `CA1001StubAnalyzer` does for UTF3003. No dummy declares a method with an underscore in its name, so the stub needs no exclusion. Fixtures cover the four attributes, an attribute derived from `TestAttribute`, an attribute implementing `ISimpleTestBuilder` directly (declared in the fixture file, because the `CombinatorialAttribute` dummy does not implement `ITestBuilder`), and, for the not-suppressed side, `[SetUp]`, `[UnitySetUp]`, and helper methods. The type, field, and parameter reports shown under "Not suppressed" are the real analyzer's behavior on locations the suppressor never examines; the stub reports on methods only, and no fixture exercises them. All the attribute and interface dummies the fixtures need already exist.
- The "neither interface exists in the compilation" case is not tested: the test harness compiles every dummy into each fixture, so the interface types are always present.

To see CA1707 on test methods again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3005
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3005" Action="None" />
</Rules>
```
