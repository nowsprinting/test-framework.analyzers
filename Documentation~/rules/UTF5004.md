# UTF5004 — Attributes implementing ITestAction must restrict their targets with AttributeUsage

Detects an attribute class that implements `NUnit.Framework.ITestAction` (directly, through a derived interface, or through a base class such as `NUnit.Framework.TestActionAttribute`) and whose effective `[AttributeUsage]` allows a target from which Unity Test Framework does not run the action for the attribute's `Targets` value. The supported targets are `AttributeTargets.Method` when `Targets` is `ActionTargets.Test`, and `AttributeTargets.Class`, `AttributeTargets.Interface`, and `AttributeTargets.Assembly` when `Targets` is `ActionTargets.Suite` or `ActionTargets.Default`. Without the restriction, the compiler accepts the attribute on an unsupported target, and the action is silently skipped there.

| Item     | Value      |
|----------|------------|
| Category | Extensions |
| Enabled  | True       |
| Severity | Warning    |
| CodeFix  | False      |

Message: "Attributes implementing ITestAction whose Targets is {0} are read only from {1}; applied to other targets, the action is silently skipped. Restrict the targets with AttributeUsage."

`{0}` is the constant value of the `Targets` property, output in single quotes like an identifier: `'ActionTargets.Test'`, `'ActionTargets.Suite'`, `'ActionTargets.Default'`, or `'ActionTargets.Test | ActionTargets.Suite'`. When the value cannot be determined, `{0}` is `not a constant` without quotes, so that the message reads "whose Targets is not a constant". `{1}` lists the supported targets for that value:

| `Targets`                                      | `{1}`                                                     | Supported `AttributeTargets`               |
|------------------------------------------------|-----------------------------------------------------------|--------------------------------------------|
| `ActionTargets.Test`                           | test methods                                              | `Method`                                   |
| `ActionTargets.Suite`, `ActionTargets.Default` | fixture classes, interfaces, and assemblies               | `Class \| Interface \| Assembly`           |
| `ActionTargets.Test \| ActionTargets.Suite`    | test methods, fixture classes, interfaces, and assemblies | `Method \| Class \| Interface \| Assembly` |
| not a constant                                 | test methods and fixture classes                          | `Method \| Class`                          |

Severity is Warning because the attribute works on the supported targets and nothing fails in the assembly that defines it. The defect surfaces at a usage site on another target, where no diagnostic and no run-time error tell the author that the action did not run. A Warning at the definition prompts the author to add the `[AttributeUsage]` that makes the compiler reject such usages (CS0592) before they spread.

> [!IMPORTANT]\
> Unity Test Framework 1.5.0 changes `GetTestActions` to walk the parent suites of the test as well (changelog entry UTF-582: "ITestAction and IOuterUnityTestAction was not triggering correctly when defined on a fixture level"), so on 1.5.0 and later a fixture-level attribute with `ActionTargets.Test` runs before every test of the fixture. The analyzer diagnoses against the 1.4.6 baseline, where it does not. If every project that consumes the attribute uses 1.5.0 or later, suppress the rule for that attribute to allow `AttributeTargets.Class` with `ActionTargets.Test`.

## Motivation

NUnit runs an [action attribute](https://docs.nunit.org/articles/nunit/extending-nunit/Action-Attributes.html) applied to a test method, a fixture class, an interface the fixture implements, or the assembly, and the `Targets` property selects whether `BeforeTest`/`AfterTest` wrap each test (`ActionTargets.Test`), the suite (`ActionTargets.Suite`), or both. `NUnit.Framework.TestActionAttribute`, NUnit's abstract base for action attributes, declares `[AttributeUsage(AttributeTargets.Assembly | AttributeTargets.Class | AttributeTargets.Interface | AttributeTargets.Method, AllowMultiple = true, Inherited = true)]` and returns `ActionTargets.Default` from `Targets` (verified against com.unity.ext.nunit 2.0.5). `NUnit.Framework.NUnitAttribute`, the base class the Unity documentation prescribes, declares no `[AttributeUsage]`, so an attribute derived from it is valid on every target (`AttributeTargets.All`).

Unity Test Framework replaces NUnit's `TestActionCommand` with its own and collects `ITestAction` at two places, each covering a different set of targets (verified against Unity Test Framework 1.4.6 source and NUnit 3.5 `ActionsHelper`):

- **Per test (`ActionTargets.Test`)**: `UnityEngine.TestTools.TestActionCommand` reads the attributes through `BeforeAfterTestCommandBase.GetTestActions`, which enumerates the custom attributes of the test method only, and invokes only actions whose `Targets` includes `ActionTargets.Test`. An attribute with `ActionTargets.Test` applied to a class, an interface, or the assembly is never seen by this command.
- **Per suite (`ActionTargets.Suite` and `ActionTargets.Default`)**: `UnityWorkItem.InitializeContext` collects the actions of a suite with NUnit's `ActionsHelper`: from the assembly attributes for the assembly suite, from the method attributes for a parameterized method suite, and from the fixture class, its base classes, and its interfaces for a fixture suite. `CompositeWorkItem.InitializeSetUpAndTearDownCommands` then runs the actions whose `Targets` includes `ActionTargets.Suite`, or equals `ActionTargets.Default` on a non-parameterized suite, once around the suite. Actions found there whose `Targets` includes `ActionTargets.Test` are added to `UnityTestExecutionContext.UpstreamActions`, which nothing in Unity Test Framework reads; NUnit's own `TestActionCommand`, which reads it, is not used.

The two places together give the supported targets per `Targets` value. With `ActionTargets.Test`, only a method-level attribute runs. With `ActionTargets.Suite` or `ActionTargets.Default`, a class-, interface-, or assembly-level attribute runs once around the suite; a method-level attribute runs only when the method is parameterized (around its method suite) and is skipped on a plain test method. With both flags, each target runs the part that applies to it. The [OuterUnityTestAction](https://docs.unity3d.com/Manual/test-framework/reference-outerunitytestaction.html) page follows this split: `[TestActionOnSuite]` (`ActionTargets.Suite`) is applied to the fixture class and `[TestActionOnTest]` (`ActionTargets.Test`) to the test methods.

On every unsupported combination the compiler accepts the attribute, the tests run, and the action never runs. The mistake is silent: no diagnostic, no run-time error, and the test passes without the set-up the author expected. Declaring `[AttributeUsage]` with the supported targets turns the mistake into compile error CS0592 ("Attribute 'X' is not valid on this declaration type") at the usage site.

### Why existing analyzers cannot be used instead

The .NET analyzer CA1018 ("Mark attributes with AttributeUsageAttribute") reports an attribute class that has no `[AttributeUsage]`. It only checks presence, not the targets, and it skips abstract classes and every class whose base type is not exactly `System.Attribute` (verified against `MarkAttributesWithAttributeUsage.cs` in dotnet/sdk; the rule is enabled as a suggestion). An attribute derived from `NUnitAttribute` or `TestActionAttribute` is never reported by CA1018, and an attribute derived from `TestActionAttribute` satisfies CA1018 while still accepting `Method` for a suite action and `Assembly` and `Interface` for a test action.

NUnit.Analyzers has no rule that inspects implementations of `ITestAction`. Verified with NUnit.Analyzers 3.9.0.

## Bad

```csharp
using System;
using NUnit.Framework;
using NUnit.Framework.Interfaces;

// No AttributeUsage: valid on every target, but a Test action is read only from test methods
public class LogAroundTestAttribute : NUnitAttribute, ITestAction   // UTF5004 at 'ITestAction'
{
    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => ActionTargets.Test;
}

// AttributeUsage allows Method: a Suite action on a plain test method is skipped
[AttributeUsage(AttributeTargets.Method | AttributeTargets.Class)]
public class LogAroundFixtureAttribute : NUnitAttribute, ITestAction   // UTF5004 at 'ITestAction'
{
    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => ActionTargets.Suite;
}

// Inherits AttributeUsage(Assembly | Class | Interface | Method) and Targets (Default) from TestActionAttribute
public class LogAroundSuiteAttribute : TestActionAttribute   // UTF5004 at 'LogAroundSuiteAttribute'
{
    public override void BeforeTest(ITest test)
    {
    }
}

// Targets is not a constant: read only from test methods and fixture classes
public class ConfigurableActionAttribute : NUnitAttribute, ITestAction   // UTF5004 at 'ITestAction'
{
    private readonly ActionTargets _targets;

    public ConfigurableActionAttribute(ActionTargets targets)
    {
        _targets = targets;
    }

    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => _targets;
}

[LogAroundTest]   // Compiles, but BeforeTest and AfterTest never run
public class MyTest
{
    [Test]
    [LogAroundFixture]   // Compiles, but BeforeTest and AfterTest never run
    public void SyncTest()
    {
    }
}
```

## Good

```csharp
using System;
using NUnit.Framework;
using NUnit.Framework.Interfaces;

[AttributeUsage(AttributeTargets.Method)]
public class LogAroundTestAttribute : NUnitAttribute, ITestAction
{
    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => ActionTargets.Test;
}

[AttributeUsage(AttributeTargets.Class | AttributeTargets.Interface | AttributeTargets.Assembly)]
public class LogAroundFixtureAttribute : NUnitAttribute, ITestAction
{
    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => ActionTargets.Suite;
}

// Narrows the AttributeUsage inherited from TestActionAttribute
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Interface | AttributeTargets.Assembly, AllowMultiple = true, Inherited = true)]
public class LogAroundSuiteAttribute : TestActionAttribute
{
    public override void BeforeTest(ITest test)
    {
    }
}

[AttributeUsage(AttributeTargets.Method | AttributeTargets.Class | AttributeTargets.Interface | AttributeTargets.Assembly)]
public class LogAroundEverythingAttribute : NUnitAttribute, ITestAction
{
    public void BeforeTest(ITest test)
    {
    }

    public void AfterTest(ITest test)
    {
    }

    public ActionTargets Targets => ActionTargets.Test | ActionTargets.Suite;
}

[LogAroundFixture]
[LogAroundSuite]
public class MyTest
{
    [Test]
    [LogAroundTest]
    [LogAroundEverything]
    public void SyncTest()
    {
    }
}
```

## Notes

- The rule inspects every class declaration in the compilation that derives from `System.Attribute` (at any depth) and implements `NUnit.Framework.ITestAction` or an interface derived from it, and reports the class when the effective `AttributeUsage` allows a target outside the supported set for its `Targets` value. A class that implements the interface but does not derive from `System.Attribute` is not reported: it cannot be applied anywhere.
- The diagnostic is reported at the base list entry that names the interface. When the class inherits the interface from a base class (`NUnit.Framework.TestActionAttribute`, or a user-defined abstract attribute) and its own base list does not name it, the diagnostic is reported at the class name. An abstract base class in the compilation and the classes derived from it are each reported; restricting the base class fixes all of them when they share its `Targets`, because the derived classes inherit its `[AttributeUsage]`.
- The effective `AttributeUsage` follows the compiler: the `[AttributeUsage]` applied to the class itself, else the one applied to the nearest base class that has one, else `AttributeTargets.All`. Roslyn exposes no public API for this lookup, so the analyzer walks `BaseType` until it finds an `AttributeUsageAttribute` or reaches `System.Attribute`. Only `ValidOn` is inspected; `AllowMultiple` and `Inherited` are not.
- The `Targets` value is taken from the `Targets` property declared in the class (an implicit or explicit interface implementation, as an expression-bodied property or a getter whose body is a single `return` statement) when the returned expression is a compile-time constant of type `ActionTargets`. When the class does not declare `Targets`, the nearest base class in the compilation that declares it is used; a base class from metadata yields `ActionTargets.Default` when it is `NUnit.Framework.TestActionAttribute` and `not a constant` otherwise. A getter with more than one statement, or a returned expression that is not a constant (a field, a constructor argument, a computed value), yields `not a constant`.
- `ActionTargets.Default` is treated as `ActionTargets.Suite`: `CompositeWorkItem` applies it to the suite (except a parameterized method suite) and never to the test. A `Targets` value that names no known member, such as `(ActionTargets)4`, is treated as `not a constant`.
- With `ActionTargets.Suite` or `ActionTargets.Default`, `AttributeTargets.Method` is excluded even though the action runs around the method suite of a parameterized test method: on a non-parameterized test method the same attribute is skipped, and the rule cannot tell at the definition which methods it will be applied to.
- Interface declarations that derive from the interface are not reported; the classes that implement the derived interface are.
- For a partial class, the diagnostic is reported in the declaration that names the interface, or in the first declaration when no declaration names it. `[AttributeUsage]` and `Targets` are looked up across all declarations of the class.
- Only class declarations are inspected. Record and struct declarations are not, because an attribute must be a class. A generic class is inspected like any other class.
- The diagnostic covers the whole base list entry even when it is written with a namespace qualifier.
- A class that also implements `UnityEngine.TestTools.IOuterUnityTestAction` is reported by [UTF5003](UTF5003.md) as well; the two rules agree only on `AttributeTargets.Method`, so such a class must be restricted to methods and use `ActionTargets.Test`.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF5004.severity = suggestion
```
