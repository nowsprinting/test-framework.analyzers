# UTF2006 — Property constraints, Ordered.By, and List.Map(...).Property lookup properties that managed code stripping can remove

Detects every property named by a string (`Has.Property("ParamName")`, `.With.Property("ParamName")`, `Is.Ordered.By("Name")`, and `List.Map(...).Property("Name")`), and the property shorthands `Has.Length`, `Has.Count`, `Has.Message`, and `Has.InnerException` whose property is not referenced by NUnit itself. NUnit finds the property with reflection at runtime, so the Unity linker sees no reference to it and can remove it from a Player build. Constraints in a test that never runs on the Player are not reported: a test method, fixture, or assembly that `[UnityPlatform]` limits to the Editor platforms with `include`, and a file under an `Editor` directory (see Notes).

| Item     | Value      |
|----------|------------|
| Category | Assertion  |
| Enabled  | True       |
| Severity | Suggestion |
| CodeFix  | False      |

Message: "'{0}' is looked up by name at runtime and managed code stripping can remove it: the test fails on the Player. Exclude the test from Player runs with [UnityPlatform] limited to the Editor platforms, or read the property directly in the actual value."

`{0}` is the name of the type that declares the property and the property name, e.g. `FileInfo.Length` or `ArgumentException.ParamName`, when the property resolves on the target type (see Notes). Otherwise, for a property named by a string, it is the name as written, e.g. `ParamName`, or the source text of the argument when the name is not a constant, e.g. `name`. The diagnostic is reported at the part of the constraint chain that names the property: the `Property(...)` invocation, the `Length`, `Count`, `Message`, or `InnerException` member access, the `By(...)` invocation, or the `Property(...)` invocation on `List.Map(...)`.

Severity is Suggestion. The test runs and passes in the Editor, and it fails only in a Player test run with managed code stripping enabled. Even at the High stripping level the getter is removed only when nothing else in the build references it, which this rule cannot see (see Notes). An error or a warning would flag code that works for every project that runs its tests only in the Editor. Suggestions appear in the IDE; raise the severity to `warning` (see the end of Notes) to report them in the compiler output as well.

## Other workarounds

Besides the fixes in Good, the following also avoid the failure. The diagnostic remains, because the rule does not see them; suppress it with `#pragma warning disable UTF2006` or `.editorconfig`.

### Compile the test only in the Editor

Wrap the test in `#if UNITY_EDITOR`, so that it is not compiled into the Player build:

```csharp
#if UNITY_EDITOR
[Test]
public void FileLength()
{
    Assert.That(new FileInfo(Path), Has.Length.GreaterThan(128));
}
#endif
```

### Preserve the property with a link.xml file

Preserve the property in a [link.xml](https://docs.unity3d.com/Manual/managed-code-stripping-xml-formatting.html) file under `Assets/`, so that the Unity linker keeps it in the Player build:

```xml
<linker>
  <assembly fullname="mscorlib">
    <type fullname="System.IO.FileInfo">
      <property name="Length" />
    </type>
    <type fullname="System.ArgumentException">
      <property name="ParamName" />
    </type>
  </assembly>
</linker>
```

## Motivation

The constraints this rule detects name the property as a string. `PropertyConstraint.ApplyTo` and `PropertyExistsConstraint.ApplyTo` call `Type.GetProperty(name, BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.Instance)` on the type of the actual value, and `PropertyConstraint.ApplyTo` reads the value with `PropertyInfo.GetValue`. `ListMapper.Property` uses the same binding flags on the type of each element. `Has.Length`, `Has.Count`, `Has.Message`, and `Has.InnerException` (and the same members on `ConstraintExpression`, e.g. `.With.Message`) are shorthands that call `Property("Length")`, `Property("Count")`, `Property("Message")`, and `Property("InnerException")`. `CollectionOrderedConstraint.Matches` calls `Type.GetProperty(name)` (public properties only) on the type of each element for the property given to `By(...)`.

The Unity linker cannot follow a property name passed as a string to NUnit, so the getter is removed from the Player build unless other code references it. The [Managed Stripping Level](https://docs.unity3d.com/Manual/managed-code-stripping-configure.html) decides what is searched for unused code:

- **Minimal**, the default for the IL2CPP scripting backend, searches only UnityEngine and the .NET class libraries. A getter of a class library type such as `FileInfo.Length` or `ArgumentException.ParamName` is removed when the test is the only code that reads it.
- **Low**, **Medium**, and **High** also search user-written assemblies, so a getter of a type declared in the project or in a package can be removed too.
- **Disabled**, the default for the Mono scripting backend, removes nothing.

The rule targets the High level: a property that High can remove is reported, whichever assembly declares it.

When the property is removed, `GetProperty` returns `null` and the test fails on the Player:

- A property constraint with a further constraint (`Has.Length.GreaterThan(128)`, `.With.Property("ParamName").EqualTo("path")`) throws `ArgumentException` ("Property Length was not found").
- A property existence constraint (`Has.Property("ParamName")` alone) fails the assertion.
- `Is.Ordered.By(...)` throws `NullReferenceException`, because it reads the value without checking the result of `GetProperty`.
- `List.Map(...).Property(...)` throws `ArgumentException` ("{0} does not have a {1} property", with the element and the property name).

Reading the property in the actual value (`Assert.That(new FileInfo(path).Length, Is.GreaterThan(128))`) puts a call to the getter in the test assembly. The linker sees this reference and keeps the getter.

A property named by a string is reported whatever the type of the actual value, whether the property exists, and wherever the constraint is written: the High level can remove any property, and the type NUnit looks the name up on is often not known at compile time (an `object` actual value, a constraint stored in a variable, a subclass at runtime).

A shorthand whose getter NUnit itself calls is not reported. At the Minimal level `nunit.framework.dll` is not searched for unused code, so its references keep the class library members they call. At the High level `nunit.framework.dll` is searched too, and such a getter is kept only while the NUnit code that calls it is kept; the rule assumes that it is, to keep the suggestion free of noise on shorthands such as `Has.Count`, which are common. `Exception.Message`, `Exception.InnerException`, `String.Length`, `Array.Length`, and `ICollection.Count` are among these getters, so `Has.Message`, `.With.InnerException`, `Has.Length` on a string or an array, and `Has.Count` on a collection are not reported (see Notes for the full list).

Verified against `nunit.framework.dll` in `com.unity.ext.nunit` 2.0.5 by reading its IL: `PropertyConstraint.ApplyTo`, `PropertyExistsConstraint.ApplyTo`, `CollectionOrderedConstraint.Matches`, and `ListMapper.Property` call `Type.GetProperty` with the name, and `Has.get_Length` and `ConstraintExpression.get_Length` (and their `Count`, `Message`, and `InnerException` counterparts) pass the property name to `Property(string)`. Other APIs of the constraint model use reflection too, but with a name fixed by NUnit rather than given by the test, so they are out of scope:

- `Is.EqualTo` reads `KeyValuePair<TKey, TValue>.Key` and `Value` by name; NUnit also calls both getters directly, so they are kept.
- `Is.EqualTo` looks up `IEquatable<T>.Equals`, and the Unity customization of `Is.EqualTo` looks up `GetInstanceID` on a `UnityEngine.Object`. Both check the `MethodInfo` for `null` and fall back to `Object.Equals`, so a removed method does not fail the test.
- `Is.GreaterThan` and the other comparison constraints look up `CompareTo` only when the value does not implement the non-generic `IComparable`.

`Has.Attribute<T>()` reads custom attributes with `GetCustomAttributes`; whether the linker removes custom attributes was not verified, so it is out of scope too. Unity Test Framework 1.6.0 ships no `link.xml` and no `IUnityLinkerProcessor` that preserves them.

## Bad

```csharp
using System;
using System.IO;
using NUnit.Framework;

public class StrippedPropertyTest
{
    private const string Path = "Assets/data.bin";

    private static void Load(string path) => throw new ArgumentNullException(nameof(path));

    [Test]
    public void FileLength()
    {
        Assert.That(new FileInfo(Path), Has.Length.GreaterThan(128)); // UTF2006: 'FileInfo.Length'
    }

    [Test]
    public void ParamName()
    {
        Assert.That(() => Load(null),
            Throws.TypeOf<ArgumentNullException>().With.Property("ParamName").EqualTo("path")); // UTF2006: 'ArgumentException.ParamName'
    }
}
```

## Good

Exclude the test from Player runs with the [UnityPlatform](https://docs.unity3d.com/Packages/com.unity.test-framework@1.4/manual/reference-attribute-unityplatform.html) attribute limited to the Editor platforms, so that it runs only in the Editor. Otherwise, read the property directly in the actual value.

```csharp
using System;
using System.IO;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

public class StrippedPropertyTest
{
    private const string Path = "Assets/data.bin";

    private static void Load(string path) => throw new ArgumentNullException(nameof(path));

    [Test]
    [UnityPlatform(RuntimePlatform.OSXEditor, RuntimePlatform.WindowsEditor, RuntimePlatform.LinuxEditor)]
    public void FileLengthInEditor()
    {
        Assert.That(new FileInfo(Path), Has.Length.GreaterThan(128));
    }

    [Test]
    public void FileLength()
    {
        Assert.That(new FileInfo(Path).Length, Is.GreaterThan(128));
    }

    [Test]
    public void ParamName()
    {
        var ex = Assert.Throws<ArgumentNullException>(() => Load(null));
        Assert.That(ex.ParamName, Is.EqualTo("path"));
    }

    [Test]
    public void ExceptionMessage()
    {
        // Exception.Message is referenced by NUnit, so the rule does not report it
        Assert.That(() => Load(null), Throws.ArgumentNullException.With.Message.Contains("path"));
    }
}
```

## Notes

- A property named by a string is reported at every invocation of `Has.Property(string)`, `ConstraintExpression.Property(string)`, `CollectionOrderedConstraint.By(string)`, and `ListMapper.Property(string)`, also outside `Assert.That` (e.g. a constraint stored in a variable) and also for a name that the type does not have. A name that does not exist fails in the Editor as well; NUnit.Analyzers reports the simplest cases of it as NUnit2022 (Error), for `Has` constraints on the actual value without `All` or `Some`.
- A shorthand (`Length`, `Count`, `Message`, `InnerException` on `Has` or `ConstraintExpression`) is resolved on a target type from the constraint chain of an `Assert.That` or `Assume.That` invocation. A property named by a string in the same chain is resolved the same way, only to name its declaring type in the message; for `Is.Ordered.By(...)` and `.Then.By(...)` the target type is the element type, and for `List.Map(collection).Property(...)` it is the element type of `collection`:
  - After `Throws.TypeOf<T>()`, `Throws.InstanceOf<T>()`, `Is.TypeOf<T>()`, or `Is.InstanceOf<T>()` followed by `.With` or `.And`, the target type is `T`. After `Throws.Exception`, `Throws.ArgumentException`, `Throws.ArgumentNullException`, `Throws.InvalidOperationException`, and `Throws.TargetInvocationException`, it is that exception type.
  - After a property step that is not yet resolved to a constraint (`Has.Property("File").With.Length`), it is the type of that property, because `ConstraintExpression.With` is a prefix operator and the shorthand reads the value of the property.
  - After a resolved constraint followed by `.With` or `.And` (`Has.Property("Directory").Not.EqualTo(null).And.Length`), it is the target type of that constraint, because `Constraint.With` is `Constraint.And` and the shorthand reads the same actual value.
  - After `All`, `Some`, `None`, or `Exactly(n)`, it is the element type of the current target type (the `T` of the `IEnumerable<T>` it implements).
  - Otherwise, it is the static type of the actual value.
- The property is resolved like the runtime lookup: an instance property of that name, public or not, declared on the target type or inherited. When the target type is an interface, the interfaces it inherits are searched too. Indexers are never matched.
- A shorthand is not reported when:
  - The target type cannot be resolved: the static type is `object`, `dynamic`, a type parameter, or `System.Type`, the element type of a non-generic collection is unknown, or the constraint is stored in a variable or returned by a helper method.
  - The target type has no property of that name, e.g. `Has.Length` on a `FileSystemInfo` variable that holds a `FileInfo`.
  - The getter of the property is referenced by `nunit.framework.dll`, or overrides or implements such a getter (e.g. `MemoryStream.Length` overrides `Stream.Length`, and `HashSet<T>.Count` implements `ICollection<T>.Count`). The list below is taken from the IL of `nunit.framework.dll` in `com.unity.ext.nunit` 2.0.5. `UnityEngine.TestRunner` also references getters, but it is compiled from the Unity Test Framework package source, so its references change with the package version; they are not in the list.
- The list is a heuristic at the Low, Medium, and High levels. `nunit.framework.dll` is searched as well, and a listed getter is kept only while the NUnit code that calls it is kept; a test that fails because a listed getter is removed is not reported.
- The rule does not see other references to the getter. A getter that other code in the Player build calls, e.g. `fileInfo.Length` read elsewhere in the test assembly, is kept but still reported. Suppress the diagnostic at that site with `#pragma warning disable UTF2006`.
- A constraint in a test that never runs on the Player is not reported:
  - A `[UnityPlatform]` attribute limits the test to the Editor platforms: its include list, given as constructor arguments or as the named `include` argument, is not empty and has only `OSXEditor`, `WindowsEditor`, and `LinuxEditor`. When several `[UnityPlatform]` attributes apply, one such attribute is enough, because NUnit skips the test when any of them does not support the platform.
  - On a test method, the attribute excludes the constraints in that method, including lambdas and local functions in it. On a fixture or an assembly, it excludes every constraint in that type or assembly, including setup methods, helper methods, and field initializers, because NUnit skips the whole suite.
  - The file path contains an `Editor` directory segment, e.g. `Assets/Tests/Editor/FileTest.cs`. The segment is matched case-sensitively, between `/` or `\` separators, so `Assets/EditorTests/FileTest.cs` and `Assets/editor/FileTest.cs` do not match. This stands in for an Edit mode test assembly, whose asmdef the rule cannot see; a Play mode test under an `Editor` directory is not reported either.
- A `[UnityPlatform]` attribute does not exclude the test in the following cases:
  - Its `exclude` list lists every Player. The Player values of `RuntimePlatform` differ between Unity versions, so such a list cannot be verified.
  - It is on a method other than a test method, e.g. a `[SetUp]` method, which NUnit does not apply it to.
  - It is on the class that contains a nested fixture, or on a base class of the fixture. NUnit does not apply the attributes of an outer class to a nested fixture; attributes of a base class are not checked by the rule.
- A static helper method in an Editor-only fixture is not reported even when a test in another fixture calls it on the Player.
- `#if UNITY_EDITOR` and link.xml files are not exclusion conditions (see Other workarounds). Conditional compilation has many forms, and a link.xml file is not part of the compilation.
