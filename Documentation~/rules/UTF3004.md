# UTF3004 — Suppress NUnit1028 (The non-test method is public) on UnitySetUp, UnityOneTimeSetUp, UnityTearDown, and UnityOneTimeTearDown methods

Suppresses NUnit1028 ("The non-test method is public") reported by NUnit.Analyzers on a method marked with `UnitySetUpAttribute`, `UnityOneTimeSetUpAttribute`, `UnityTearDownAttribute`, or `UnityOneTimeTearDownAttribute`. NUnit1028 exempts methods marked with NUnit's `SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, and `OneTimeTearDownAttribute`; this suppressor extends the exemption to their Unity Test Framework counterparts.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | NUnit1028  |
| CodeFix    | False      |

Justification: "Method is a UnitySetUp, UnityOneTimeSetUp, UnityTearDown, or UnityOneTimeTearDown method."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

> [!NOTE]\
> `UnityOneTimeSetUpAttribute` and `UnityOneTimeTearDownAttribute` are available only in Unity Test Framework 1.5.0 or later.
> Since Unity Test Framework 1.4.6, the package is a core package bundled with the Unity Editor and cannot be upgraded independently; 1.5.0 is bundled with Unity 6000.0.44f1 or later.

## Motivation

NUnit1028 (`NonTestMethodAccessibilityLevelAnalyzer`, default severity Info, verified in NUnit.Analyzers 3.9.0) reports every `public`, `internal`, or `protected internal` ordinary method of a test fixture that is not test-related, except `IDisposable.Dispose` implementations. A class counts as a test fixture when it declares at least one test-related method; a class without any is not reported at all. "Test-related" means the method (or a method it overrides) is marked with an attribute that derives from `ITestBuilder` or `ISimpleTestBuilder`, or with an attribute whose type is exactly NUnit's `SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, or `OneTimeTearDownAttribute` (`IsSetUpOrTearDownMethodAttribute`). `UnityTestAttribute` implements `ISimpleTestBuilder`, so `[UnityTest]` methods are recognized. `UnitySetUpAttribute`, `UnityOneTimeSetUpAttribute`, `UnityTearDownAttribute`, and `UnityOneTimeTearDownAttribute` derive from `NUnitAttribute`, not from the NUnit setup and teardown attributes, so the exact-type check never matches them. A fixture with a `[Test]` or `[UnityTest]` method and a public `[UnitySetUp]` method therefore gets NUnit1028 on the `[UnitySetUp]` method.

The [Unity Test Framework manual](https://docs.unity3d.com/Manual/test-framework/reference-unitysetup-and-unityteardown.html) describes `[UnitySetUp]` and `[UnityTearDown]` as "equivalent to the NUnit `[SetUp]` and `[TearDown]` attributes, with the exception that they allow for yielding instructions for the Unity Editor", and `[UnityOneTimeSetUp]` and `[UnityOneTimeTearDown]` likewise as equivalent to `[OneTimeSetUp]` and `[OneTimeTearDown]`. They are setup and teardown methods of the fixture, invoked by the test runner and not by other classes, which is the reason NUnit1028 exempts NUnit's own setup and teardown methods. The reason applies unchanged.

NUnit1028 has a code fix (`NonTestMethodAccessibilityLevelCodeFix`, "Make non-test method private") that replaces the `public` or `internal` modifier with `private`. The result compiles. Unity Test Framework discovers the hook methods with NUnit's `Reflect.GetMethodsWithAttribute`, whose binding flags include `NonPublic`, so a private hook declared in the fixture itself still runs. [`Type.GetMethods`](https://learn.microsoft.com/en-us/dotnet/api/system.type.getmethods#system-type-getmethods(system-reflection-bindingflags)) never returns private methods declared in a base class ("Only protected and internal methods on base classes are returned; private methods on base classes are not returned"), however, so a private hook declared in a base class silently stops running for the derived fixtures. Declaring the hooks in a base class shared by several fixtures is the pattern the attributes' own XML documentation shows ("Base and Derived class example"), every hook in that example is public, and the base class there also declares `[SetUp]` and `[TearDown]` methods, which make it a fixture for NUnit1028 and get its `[UnitySetUp]` and `[UnityTearDown]` methods reported. Applying the code fix there is a regression that no test reports.

Without this suppressor, every such hook method has to be `private` (and kept out of base classes), `protected` (which reads as an extension point that does not exist), or annotated with a `#pragma` or `[SuppressMessage]`.

## Suppressed

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnitySetUp]
    public IEnumerator SetUp()   // NUnit1028 reported by NUnit.Analyzers, suppressed by UTF3004
    {
        yield return null;
    }

    [UnityTearDown]
    public IEnumerator TearDown()   // NUnit1028 reported by NUnit.Analyzers, suppressed by UTF3004
    {
        yield return null;
    }

    [Test]
    public void MyTestMethod()
    {
    }
}
```

## What the NUnit1028 code fix produces

The code fix replaces `public` with `private`. The hook still runs when it is declared in the fixture itself. Declared in a base class, it is no longer discovered for the derived fixtures, and their tests run without it:

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTestBase
{
    [SetUp]
    public void SetUp()   // Makes MyTestBase a fixture for NUnit1028, so UnitySetUp below is reported
    {
    }

    [UnitySetUp]
    private IEnumerator UnitySetUp()   // After the code fix: not discovered for MyTest, the scene is never loaded
    {
        yield return UnityEngine.SceneManagement.SceneManager.LoadSceneAsync("MyScene");
    }
}

public class MyTest : MyTestBase
{
    [Test]
    public void MyTestMethod()
    {
    }
}
```

## Not reported

NUnit1028 itself stays silent on a class that has no test-related method, such as a base class that declares only hook methods. Nothing is reported, so nothing is suppressed:

```csharp
using System.Collections;
using UnityEngine.TestTools;

public class MyTestBase   // Not a test fixture for NUnit1028: no [Test], [UnityTest], [SetUp], ... method
{
    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
    }
}
```

## Not suppressed

A public method without any of the four attributes is a helper, and NUnit1028 is right about it:

```csharp
using System.Collections;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnitySetUp]
    public IEnumerator SetUp()   // Suppressed by UTF3004
    {
        yield return null;
    }

    public void Helper()   // NUnit1028 reported by NUnit.Analyzers, not suppressed
    {
    }

    [Test]
    public void MyTestMethod()
    {
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `UnityEngine.TestTools.UnitySetUpAttribute`, `UnityEngine.TestTools.UnityOneTimeSetUpAttribute`, `UnityEngine.TestTools.UnityTearDownAttribute`, and `UnityEngine.TestTools.UnityOneTimeTearDownAttribute` independently and returns without suppressing only when none of them exists in the compilation. Requiring all four would silently disable the suppressor on Unity Test Framework 1.4.x, where the `UnityOneTime*` attributes do not exist. Attributes are matched by symbol, not by name, so a user-defined attribute named `UnitySetUpAttribute` in another namespace does not count.
- An NUnit1028 report is suppressed when the reported method is marked with any of the four attributes, on the method itself or on a method it overrides. The walk over overridden methods matches NUnit1028's own `IsTestRelatedMethod`, so an `override` of a base hook is treated the same way NUnit1028 treats an `override` of a `[SetUp]` method. The shared `UnityHookMethodAnalysis.HasAnyAttribute` helper takes the attribute symbols as a `params` array and skips null entries, so the four lookups are passed in one call.
- Only NUnit1028 reports whose location resolves to a method declaration are handled. NUnit1028 reports at `method.Locations[0]`, the method identifier, whose enclosing node is the method declaration.
- Accessibility is not examined. NUnit1028 also reports `internal` and `protected internal` methods, and a hook with either accessibility is suppressed as well; the attribute is the criterion.
- The return type is not examined. Unity Test Framework ignores a hook method whose return type is not `IEnumerator`, so NUnit1028 is arguably right about a `[UnitySetUp] public void` method, but a method marked with the attribute is a hook by intent, and whether it is a valid one is a separate concern, like UTF3003 not checking that the teardown disposes the field.
- Methods marked with NUnit's `SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, or `OneTimeTearDownAttribute` are already exempt in NUnit1028 and are not the suppressor's concern.
- The suppressor has no effect when NUnit.Analyzers is not installed, because there is no NUnit1028 to suppress.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against NUnit.Analyzers 3.9.0 (`NonTestMethodAccessibilityLevelAnalyzer`, `IMethodSymbolExtensions.IsTestRelatedMethod`, `AttributeDataExtensions.IsSetUpOrTearDownMethodAttribute`), Unity Test Framework 1.6.0 (the four attributes derive from `NUnitAttribute`; `UnityTestAttribute` implements `ISimpleTestBuilder`; hooks are discovered in `BeforeAfterTestCommandBase.GetMethodsWithAttributeFromFixture`), and `com.unity.ext.nunit` 2.0.5, whose `Reflect.GetMethodsWithAttribute` (NUnit 3.5) uses `BindingFlags.Public | NonPublic | Instance | Static` plus `FlattenHierarchy`.
- The test does not run the real NUnit.Analyzers; a test-only stub (`NUnit1028StubAnalyzer`, default severity Info like the real rule, since Roslyn never passes an Error-by-default diagnostic to a suppressor) reports NUnit1028 at the identifier of every public ordinary method that is not marked with `[Test]`, `[UnityTest]`, or one of NUnit's four setup and teardown attributes, as `NUnit2045StubAnalyzer` does for UTF3001. Without that exclusion the fixture's own `[Test]` method would appear as an unsuppressed NUnit1028 in the expectations. The stub reproduces the fixture gate (report only in a class that declares a test-related method), because the dummies themselves declare public methods and would otherwise be reported. The "Not reported" case above is the real analyzer's behavior, not the suppressor's, and no fixture is added for it; in the override fixture the abstract base hook is likewise not reported, and only the override in the derived fixture is expected. All the attribute dummies the fixtures need already exist.
- The "none of the attributes exists in the compilation" case is not tested: the test harness compiles every dummy into each fixture, so the attribute types are always present.

To see NUnit1028 again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3004
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3004" Action="None" />
</Rules>
```
