# UTF3006 — Suppress VSTHRD200 (Use Async suffix for async methods) on test methods

Suppresses VSTHRD200 ("Use 'Async' suffix for async methods") reported by Microsoft.VisualStudio.Threading.Analyzers on a method marked with an attribute that implements `NUnit.Framework.Interfaces.ITestBuilder` or `NUnit.Framework.Interfaces.ISimpleTestBuilder`. `TestAttribute`, `UnityTestAttribute`, `TestCaseAttribute`, and `TestCaseSourceAttribute` implement one of them, and so does every attribute derived from them.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | VSTHRD200  |
| CodeFix    | False      |

Justification: "Method is a test method; its name is read in test reports, not by a caller deciding whether to await it."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

## Motivation

VSTHRD200 (`VSTHRD200UseAsyncNamingConventionAnalyzer`, verified in Microsoft.VisualStudio.Threading.Analyzers 18.7.23) reports every method and local function whose name disagrees with its return type: a method returning an awaitable type whose name does not end with `Async` ("Use 'Async' suffix in names of methods that return an awaitable type"), and a method returning a non-awaitable type whose name does end with `Async` ("Avoid 'Async' suffix in names of methods that do not return an awaitable type"). The two cases are two `DiagnosticDescriptor`s sharing the single ID `VSTHRD200`, both created with `defaultSeverity: DiagnosticSeverity.Warning` and `isEnabledByDefault: true`. Warning is not Error, so Roslyn hands the diagnostic to suppressors. A return type is awaitable to the rule when it is `System.Threading.Tasks.Task` or `Task<TResult>`, `IAsyncEnumerable<T>` or a type implementing it, or a type marked with `AsyncMethodBuilderAttribute`, which covers `ValueTask`, `UnityEngine.Awaitable`, and `UniTask`. `IEnumerator` is not awaitable to the rule. The rule skips property accessors, the entry point, `DisposeAsyncCore`, overrides, and interface implementations; it has no exemption for test methods. It reports at `methodSymbol.Locations[0]`, the method identifier.

VSTHRD200 has a code fix ("Rename to {0}", `VSTHRD200UseAsyncNamingConventionCodeFix`) that renames the method with `Renamer.RenameSymbolAsync`, adding or removing the suffix. The result compiles and the test still runs; the cost is the name shown in the Test Runner window and in every test report.

The `Async` suffix is the Task-based Asynchronous Pattern's signal to a caller that the method returns something to await. A test method has no caller. The test runner invokes it through reflection and chooses how to run it from its return type, not its name: Unity Test Framework's `TestCommandBuilder` picks `TaskTestMethodCommand` when `test.Method.ReturnType.Type == typeof(Task)` and `EnumerableTestMethodCommand` when it is `IEnumerator` (verified in Unity Test Framework 1.6.0). The name is read only by a person looking at a report, where the suffix carries no information, and where the `Method_State_ExpectedResult` convention (see UTF3005) already fixes the shape of the name. The reverse direction is as inapplicable: a coroutine-style test method named `...Async` returns `IEnumerator`, which the rule does not count as awaitable, yet nobody is misled, because nobody awaits it.

Microsoft.VisualStudio.Threading.Analyzers ships no suppressor at all (no `DiagnosticSuppressor` is referenced by the 18.7.23 assemblies), and NUnit.Analyzers has none for VSTHRD200 (its suppressors are NUnit3001 through NUnit3004, verified in NUnit.Analyzers 3.9.0). Without this suppressor, a project either disables VSTHRD200 for the whole test assembly with `dotnet_diagnostic.VSTHRD200.severity = none`, which also silences it on helper methods and test utilities where the rule is right, renames every async test method with a suffix it does not need, or annotates every one with a `#pragma` or `[SuppressMessage]`.

### Why the criterion is the builder interface, not the attribute types

The criterion is the one UTF3005 uses, for the reasons given there (["Why the criterion is the builder interface, not the four attribute types"](UTF3005.md#why-the-criterion-is-the-builder-interface-not-the-four-attribute-types)): NUnit's `DefaultTestCaseBuilder.CanBuildFrom` runs a method as a test exactly when one of its attributes implements `ITestBuilder` or `ISimpleTestBuilder`. Interface implementation is inherited, so an attribute derived from `TestAttribute`, `UnityTestAttribute`, `TestCaseAttribute`, or `TestCaseSourceAttribute` is recognized without being named, and so is a user-defined attribute that implements either interface directly. A list of attribute types, or a base-class walk against a list, is not used because either would miss such attributes.

## Suppressed

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [Test]
    public async Task Add_TwoPositiveNumbers_ReturnsSum()   // VSTHRD200 (add suffix) reported by Microsoft.VisualStudio.Threading.Analyzers, suppressed by UTF3006
    {
        await Task.Yield();
    }

    [UnityTest]
    public IEnumerator LoadSceneAsync()   // VSTHRD200 (remove suffix) reported, suppressed by UTF3006
    {
        yield return null;
    }

    [TestCase(1)]
    [TestCase(2)]
    public async Task IsPositive_PositiveNumber_ReturnsTrue(int value)   // Suppressed by UTF3006
    {
        await Task.Yield();
    }

    [TestCaseSource(nameof(Cases))]
    public async Task IsPositive_FromSource_ReturnsTrue(int value)   // Suppressed by UTF3006
    {
        await Task.Yield();
    }

    private static readonly int[] Cases = { 1, 2 };
}
```

A user-defined attribute is recognized through the interface, whether it derives from one of the four attributes or implements the interface directly:

```csharp
using System.Threading.Tasks;
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using NUnit.Framework.Internal;

public class MyTestAttribute : TestAttribute   // Inherits ISimpleTestBuilder from TestAttribute
{
}

public class MyTestBuilderAttribute : NUnitAttribute, ISimpleTestBuilder
{
    public TestMethod BuildFrom(IMethodInfo method, Test suite) => new TestMethod(method, suite);
}

public class CalculatorTest
{
    [MyTest]
    public async Task Add_TwoPositiveNumbers_ReturnsSum()   // Suppressed by UTF3006
    {
        await Task.Yield();
    }

    [MyTestBuilder]
    public async Task Add_TwoNegativeNumbers_ReturnsSum()   // Suppressed by UTF3006
    {
        await Task.Yield();
    }
}
```

## What VSTHRD200 asks for instead

The code fix renames the method. The test still runs, but the Test Runner window and every report now show a suffix that tells the reader nothing:

```csharp
using System.Threading.Tasks;
using NUnit.Framework;

public class MyTest
{
    [Test]
    public async Task Add_TwoPositiveNumbers_ReturnsSumAsync()
    {
        await Task.Yield();
    }
}
```

## Not suppressed

Only test methods are suppressed. VSTHRD200 stays on setup and teardown methods, helper methods, and local functions:

```csharp
using System.Threading.Tasks;
using NUnit.Framework;

public class MyTest
{
    [SetUp]
    public async Task SetUp()   // VSTHRD200 reported by Microsoft.VisualStudio.Threading.Analyzers, not suppressed: SetUpAttribute implements neither interface
    {
        await Task.Yield();
    }

    [TearDown]
    public async Task TearDown()   // VSTHRD200 reported, not suppressed
    {
        await Task.Yield();
    }

    public async Task CreateFixture()   // VSTHRD200 reported, not suppressed
    {
        await Task.Yield();
    }

    [Test]
    public async Task Add_TwoPositiveNumbers_ReturnsSum()   // Method suppressed
    {
        async Task Prepare()   // VSTHRD200 (local function) reported, not suppressed
        {
            await Task.Yield();
        }

        await Prepare();
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `NUnit.Framework.Interfaces.ITestBuilder` and `NUnit.Framework.Interfaces.ISimpleTestBuilder` and returns without suppressing when either is missing from the compilation. Both exist in NUnit 3.5 (`com.unity.ext.nunit` 2.0.5), the baseline, so the condition is a guard against a compilation that does not reference NUnit at all rather than a version check. The lookup and the attribute check are shared with UTF1005 and UTF3005 through `TestMethodAnalysis`, so there is one definition of "test method" in the package. Interfaces are matched by symbol, not by name. `UnityTestAttribute` is not required to exist.
- A VSTHRD200 report is suppressed when the reported method is marked with an attribute whose class (`AttributeClass.AllInterfaces`) implements either interface (`TestMethodAnalysis.IsTestMethod`). Only the method's own attributes are examined. VSTHRD200 skips overrides (`IsOverride`) and interface implementations (`FindInterfacesImplemented().Any()`) before reporting, so the walk over overridden methods that UTF3004 performs for NUnit1028 has nothing to find here and is not performed.
- Only VSTHRD200 reports whose location resolves to a method declaration are handled. VSTHRD200 reports at `methodSymbol.Locations[0]`, the method identifier, whose enclosing node is the method declaration. VSTHRD200 also reports local functions; those resolve to a local function statement and are left alone, so a local function declared inside a test method is still reported.
- Both directions of VSTHRD200 are suppressed on a test method: the report asking to add the suffix (an awaitable return type without `Async`) and the report asking to remove it (a non-awaitable return type with `Async`). Both share the ID `VSTHRD200` and a suppressor matches by ID; telling them apart would need the localized message text or the undocumented `NewName` diagnostic property. Neither direction has a caller to inform, so the justification is the same.
- Setup and teardown methods (`SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, `OneTimeTearDownAttribute`, and their Unity Test Framework counterparts) are not suppressed. They implement neither interface, and their names are not shown in a test report.
- Accessibility and return type are not examined. A method marked with a builder attribute is a test method by intent; whether Unity Test Framework can run it with that return type is a separate concern (UTF1002 reports `Task<TResult>`). A test method returning `UnityEngine.Awaitable`, `UniTask`, or `ValueTask` is reported by VSTHRD200 through `AsyncMethodBuilderAttribute` and is suppressed like one returning `Task`.
- VSTHRD200 is reported only when Microsoft.VisualStudio.Threading.Analyzers is installed in the project as a Roslyn analyzer, so the suppressor has no effect otherwise.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against the Microsoft.VisualStudio.Threading.Analyzers source at tag v18.7.23 (`VSTHRD200UseAsyncNamingConventionAnalyzer.cs`, `VSTHRD200UseAsyncNamingConventionCodeFix.cs`, `Utils.cs`, and `Strings.resx`, read on 2026-09-08), the [VSTHRD200 rule documentation](https://microsoft.github.io/vs-threading/analyzers/VSTHRD200.html), NUnit.Analyzers 3.9.0 (suppressors NUnit3001 to NUnit3004 only), `com.unity.ext.nunit` 2.0.5 (NUnit 3.5: `DefaultTestCaseBuilder.CanBuildFrom`), and Unity Test Framework 1.6.0 (`TestCommandBuilder`, `UnityTestAttribute`).
- The test does not run the real Microsoft.VisualStudio.Threading.Analyzers. The real analyzer could see the fixtures (it identifies `Task` by name and namespace, not by assembly), but its remove-suffix direction fires on the `Assert` dummy's `ThrowsAsync`, `CatchAsync`, and `DoesNotThrowAsync`, which return non-awaitable types, and the dummies are compiled into every fixture. A test-only stub (`VSTHRD200StubAnalyzer`, default severity Warning like the real rule, since Roslyn never passes an Error-by-default diagnostic to a suppressor) reports VSTHRD200 at the identifier of every ordinary method that returns `Task` or `Task<TResult>` and whose name does not end with `Async`, as `CA1707StubAnalyzer` does for UTF3005. The stub reports only that direction for the same reason. The suppressor never examines the direction, so the fixture for the remove-suffix direction (a coroutine-style test method named `...Async`) would only exercise the stub and is omitted. Fixtures cover the four attributes, an attribute derived from `TestAttribute`, an attribute implementing `ISimpleTestBuilder` directly, and, for the not-suppressed side, `[SetUp]`, `[TearDown]`, a helper method, and a local function inside a test method. All the attribute and interface dummies the fixtures need already exist.
- The "neither interface exists in the compilation" case is not tested: the test harness compiles every dummy into each fixture, so the interface types are always present.

To see VSTHRD200 on test methods again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3006
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3006" Action="None" />
</Rules>
```
