# UTF3002 — Suppress CS8618 (Non-nullable field or property is uninitialized) when the member is initialized in a UnitySetUp or UnityOneTimeSetUp method

Suppresses the compiler warning CS8618 ("Non-nullable field/property must contain a non-null value when exiting constructor") on a field or property that a method marked with `UnitySetUpAttribute` or `UnityOneTimeSetUpAttribute` assigns. It is the counterpart of NUnit3002 in NUnit.Analyzers, which suppresses the same warning for `SetUpAttribute` and `OneTimeSetUpAttribute` only.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | CS8618     |
| CodeFix    | False      |

Justification: "Field/Property is initialized in UnitySetUp or UnityOneTimeSetUp method."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

> [!NOTE]\
> `UnityOneTimeSetUpAttribute` is available only in Unity Test Framework 1.5.0 or later.
> Since Unity Test Framework 1.4.6, the package is a core package bundled with the Unity Editor and cannot be upgraded independently; 1.5.0 is bundled with Unity 6000.0.44f1 or later.

## Motivation

When nullable reference types are enabled (`#nullable enable` in the source, or `-nullable:enable` in `csc.rsp`), the compiler reports CS8618 on every non-nullable field or property that is not assigned by the time a constructor exits. A test fixture initializes its members in a setup method, not in a constructor, so every such member is reported. The alternatives are declaring the member nullable, which forces a null check or the null-forgiving operator `!` at every use in every test, or assigning a placeholder in the constructor.

NUnit.Analyzers solves this for NUnit's setup attributes: NUnit3002 (`NonNullableFieldOrPropertyIsUninitializedSuppressor`) suppresses CS8618 when a method whose attribute class is named exactly `SetUpAttribute` or `OneTimeSetUpAttribute` assigns the member. The check is on the attribute class name (`AttributeClass?.Name is "SetUpAttribute" or "OneTimeSetUpAttribute"`, verified in NUnit.Analyzers 3.9.0), so `UnitySetUpAttribute` and `UnityOneTimeSetUpAttribute` never match: they derive from `NUnitAttribute`, not from the NUnit setup attributes.

The [Unity Test Framework manual](https://docs.unity3d.com/Manual/test-framework/reference-unitysetup-and-unityteardown.html) describes `[UnitySetUp]` and `[UnityTearDown]` as "equivalent to the NUnit `[SetUp]` and `[TearDown]` attributes, with the exception that they allow for yielding instructions for the Unity Editor", and `[UnityOneTimeSetUp]` and `[UnityOneTimeTearDown]` likewise as equivalent to `[OneTimeSetUp]` and `[OneTimeTearDown]`. A member assigned in a `[UnitySetUp]` method is initialized before every test as reliably as one assigned in a `[SetUp]` method, so CS8618 is noise there for the same reason NUnit3002 treats it as noise. A fixture that loads a scene in `[UnitySetUp]` and stores the objects it finds afterwards is the typical case.

Without this suppressor, a Unity project has to declare those members nullable and write `!` in every test, or disable CS8618 for the whole test assembly.

## Suppressed

```csharp
#nullable enable
using System.Collections;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.TestTools;

public class MyTest
{
    private GameObject _player;   // CS8618 reported by the compiler, suppressed by UTF3002

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return SceneManager.LoadSceneAsync("Stage");
        _player = GameObject.Find("Player");
    }

    [Test]
    public void PlayerIsActive()
    {
        Assert.That(_player.activeSelf, Is.True);
    }
}
```

## What CS8618 asks for instead

Declaring the member nullable compiles, but every use needs a null check or the null-forgiving operator:

```csharp
#nullable enable
using System.Collections;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.TestTools;

public class MyTest
{
    private GameObject? _player;

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return SceneManager.LoadSceneAsync("Stage");
        _player = GameObject.Find("Player");
    }

    [Test]
    public void PlayerIsActive()
    {
        Assert.That(_player!.activeSelf, Is.True);   // '!' in every test
    }
}
```

## Not suppressed

The member is assigned only under a condition, so the setup method does not guarantee initialization:

```csharp
#nullable enable
using System.Collections;
using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;

public class MyTest
{
    private GameObject _player;   // CS8618 reported by the compiler, not suppressed

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
        if (Application.isPlaying)
        {
            _player = GameObject.Find("Player");
        }
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `UnityEngine.TestTools.UnitySetUpAttribute` and `UnityEngine.TestTools.UnityOneTimeSetUpAttribute` independently and returns without suppressing only when neither exists in the compilation. Requiring both would silently disable the suppressor on Unity Test Framework 1.4.x, where `UnityOneTimeSetUpAttribute` does not exist. Attributes are matched by symbol, not by name, so a user-defined attribute named `UnitySetUpAttribute` in another namespace does not count.
- A CS8618 report is suppressed when a method marked with either attribute (on the method itself or on a method it overrides) assigns the member. "Assigns" follows the same walk as NUnit3002: a direct assignment (including `this.member = ...` and tuple deconstruction), an assignment inside a `try` block or its `finally` block, an assignment after a `yield return` statement, or an assignment made by a method declared in the same class that the setup method calls (directly or transitively). An assignment inside `if`, a loop, a lambda, or a local function does not count, because it does not guarantee initialization. The assigned target is compared by symbol, so a local or parameter that shares the member's name does not count either.
- Only CS8618 reports located on the field declarator or the property declaration are handled. When the fixture declares an explicit constructor, the compiler reports CS8618 on the constructor instead, and the member name is available only through Roslyn's internal diagnostic arguments; NUnit3002 reads them by reflection. This suppressor does not, and leaves such reports as they are. Test fixtures with explicit constructors are rare in Unity Test Framework, and NUnit's own guidance is to use setup methods; the reflection can be added if the case turns out to matter.
- Methods marked with `SetUpAttribute` or `OneTimeSetUpAttribute` are left to NUnit3002. This suppressor does not replace NUnit3002 when NUnit.Analyzers is not installed.
- CS8618 is reported only when nullable reference types are enabled, so the suppressor has no effect in a project that leaves them disabled.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against NUnit.Analyzers 3.9.0 and Unity Test Framework 1.6.0 (`UnitySetUpAttribute` and `UnityOneTimeSetUpAttribute` derive from `NUnitAttribute`).
- The tests need no producer stub: CS8618 comes from the compiler itself, and the test harness compiles fixtures with the nullable context enabled. A `UnitySetUpAttribute` dummy is added next to the existing `UnityOneTimeSetUpAttribute` dummy.
- The "neither attribute exists in the compilation" case is not tested: the test harness compiles every dummy into each fixture, so the attribute types are always present. Testing it would need a second harness path that excludes the dummies, which is not worth it for an early return.

To see CS8618 again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3002
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3002" Action="None" />
</Rules>
```
