# UTF5002 — Implementing IWrapTestMethod and IWrapSetUpTearDown is not recommended

Detects a class whose base list names `NUnit.Framework.Interfaces.IWrapTestMethod` or `NUnit.Framework.Interfaces.IWrapSetUpTearDown` (or an interface derived from either). Unity Test Framework cannot run the command returned by a user-defined `Wrap` on `async Task` and coroutine-style test methods, so an attribute built on these interfaces can be applied only to synchronous test methods. `NUnit.Framework.ITestAction` and `UnityEngine.TestTools.IOuterUnityTestAction` provide before/after hooks that work on every kind of test method: `ITestAction` when the hooks are synchronous, `IOuterUnityTestAction` when they need to yield.

| Item     | Value      |
|----------|------------|
| Category | Extensions |
| Enabled  | True       |
| Severity | Warning    |
| CodeFix  | False      |

Message: "Attributes implementing '{0}' cannot be applied to async and coroutine-style test methods. Implement ITestAction or IOuterUnityTestAction instead."

`{0}` is the interface named in the base list: `IWrapTestMethod` or `IWrapSetUpTearDown`. When a user-defined interface derived from one of them is named, that interface is output.

Severity is Warning because the attribute works on synchronous test methods and nothing fails at run time in the assembly that defines it. The limitation surfaces later, at each test method the attribute is applied to: UTF1005 reports the usage when the test method is in a compilation that runs the analyzers, and the test fails at run time otherwise. A Warning at the definition lets the author choose a hook that has no such limitation before the attribute spreads.

> [!NOTE]\
> On the 1.4.6 baseline, Unity Test Framework reads `ITestAction` with `ActionTargets.Test` and `IOuterUnityTestAction` from the test method only. Unity Test Framework 1.5.0 changes `GetTestActions` to walk the parent suites of the test as well (changelog entry UTF-582: "ITestAction and IOuterUnityTestAction was not triggering correctly when defined on a fixture level"), so on 1.5.0 and later a fixture-level attribute runs before every test of the fixture. See [UTF5003](UTF5003.md) and [UTF5004](UTF5004.md) for the targets each hook supports.

## Motivation

NUnit lets a custom attribute alter test execution by implementing `IWrapTestMethod` or `IWrapSetUpTearDown` ([ICommandWrapper interface](https://docs.nunit.org/articles/nunit/extending-nunit/ICommandWrapper-Interface.html)). The attribute's `Wrap` method returns a `TestCommand` whose synchronous `Execute` calls the inner command's `Execute`. Unity Test Framework lists both interfaces in the execution order on the [Actions outside of tests](https://docs.unity3d.com/Manual/test-framework/reference-actions-outside-tests.html) page, and the course section "16. Custom attributes" (with sample `16_CustomAttributes_Solution`) walks through writing an `IWrapTestMethod` attribute, so this is the pattern authors reach for first.

Unity Test Framework runs `async Task` and coroutine-style test methods through commands that implement the internal interface `IEnumerableTestMethodCommand`, and a user-defined command cannot take part in that chain. Applying a wrapper attribute to such a test method makes the test fail without running its body; see [UTF1005](UTF1005.md) for the mechanism and the combinations. As a result, every attribute built on `IWrapTestMethod` or `IWrapSetUpTearDown` carries a restriction that is invisible at its definition: it must never be applied to an `async Task` or `[UnityTest]` method. When the attribute is shared across assemblies or projects, the restriction is discovered at each usage, one failing test at a time.

Unity Test Framework runs two before/after hooks on every kind of test method, both through the same base class `BeforeAfterTestCommandBase` (verified against Unity Test Framework 1.6.0 source):

- `NUnit.Framework.ITestAction` ([Action Attributes](https://docs.nunit.org/articles/nunit/extending-nunit/Action-Attributes.html)), run by `TestActionCommand`. `BeforeTest` and `AfterTest` are synchronous `void` methods. It is NUnit's own extension point (a feature since NUnit 2.6); Unity's custom NUnit build (com.unity.ext.nunit 2.0.5, based on NUnit 3.5) ships `NUnit.Framework.ITestAction`, `NUnit.Framework.ActionTargets`, and the abstract base `NUnit.Framework.TestActionAttribute`. Unity Test Framework defines no attribute implementing it; it only runs them, through `TestActionCommand` for `ActionTargets.Test` and `CompositeWorkItem` for `ActionTargets.Suite`.
- `UnityEngine.TestTools.IOuterUnityTestAction` ([API reference](https://docs.unity3d.com/Packages/com.unity.test-framework@1.4/api/UnityEngine.TestTools.IOuterUnityTestAction.html)), run by `OuterUnityTestActionCommand`, "to provide actions to execute before setup and after teardown of tests". `BeforeTest` and `AfterTest` return `IEnumerator`. The 1.4 package documentation lists "OuterUnityTestAction" at the same positions in the execution order.

Choose by whether the hook needs to yield:

- **Synchronous hooks: `ITestAction`.** It runs immediately around the test body (positions 8 and 11 in the execution order), the closest to where `IWrapTestMethod` wraps the test (position 9). `TestActionCommand` never yields between an action and the test.
- **Hooks that need to yield: `IOuterUnityTestAction`.** `BeforeAfterTestCommandBase` drives the enumerator one step per frame and persists its position in `UnityTestExecutionContext.OuterUnityTestActionState`, so an action can yield `null` to skip frames and, in Edit Mode, yield `EnterPlayMode` and `ExitPlayMode` across a domain reload. It runs before `[UnitySetUp]` and after `[UnityTearDown]` (positions 4 and 14). A command returned by `Wrap` has a synchronous `Execute` and cannot yield at all.

Both hooks share these properties:

- **Work on every kind of test method.** `TestCommandBuilder.BuildTestCommand` always places `TestActionCommand` and `OuterUnityTestActionCommand` in the chain, regardless of the return type. The `IOuterUnityTestAction` documentation applies the same attribute to a `[Test]` `void` method and to a `[UnityTest]` `IEnumerator` method.
- **Exceptions are recorded, not escalated.** An exception thrown from `BeforeTest` or `AfterTest` is caught by `BeforeAfterTestCommandBase.ExecuteEnumerable` and recorded on the test result with a `BeforeTest`/`AfterTest` prefix. An exception from `Wrap` aborts the test run (see [UTF5001](UTF5001.md)).
- **Read from the test method.** Both commands collect the attributes from the test method, as Unity Test Framework does for `IWrapTestMethod` and `IWrapSetUpTearDown`. From 1.5.0 they also collect from every parent `TypeInfo`, so the attribute can be applied to a fixture class or a base class; `ITestAction` with `ActionTargets.Suite` is collected from the fixture class in every version.

Neither hook is a wrapper, so neither is a drop-in replacement in every respect: it cannot replace the command, so it cannot re-run the test body, catch an exception thrown by it, or alter the result. Unity Test Framework covers those needs with `RepeatAttribute`, `RetryAttribute`, and `MaxTimeAttribute`, whose commands it substitutes with enumerable implementations. `IWrapSetUpTearDown` sits between `[UnitySetUp]` and `[SetUp]` (position 6); no hook runs at exactly that position.

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers has no rule that inspects implementations of `ICommandWrapper`, `IWrapTestMethod`, or `IWrapSetUpTearDown`. Verified with NUnit.Analyzers 3.9.0.

## Bad

```csharp
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using NUnit.Framework.Internal;
using NUnit.Framework.Internal.Commands;

public class LogCommand : DelegatingTestCommand
{
    private readonly string _label;

    public LogCommand(TestCommand innerCommand, string label) : base(innerCommand)
    {
        _label = label;
    }

    public override TestResult Execute(ITestExecutionContext context)
    {
        TestContext.Out.WriteLine($"{_label}: before");
        var result = innerCommand.Execute(context);
        TestContext.Out.WriteLine($"{_label}: after");
        return result;
    }
}

public class LogAroundTestAttribute : NUnitAttribute, IWrapTestMethod   // UTF5002 at 'IWrapTestMethod'; cannot be applied to async Task or [UnityTest] methods
{
    public TestCommand Wrap(TestCommand command)
    {
        return new LogCommand(command, "test");
    }
}

public class LogAroundSetUpAttribute : NUnitAttribute, IWrapSetUpTearDown   // UTF5002 at 'IWrapSetUpTearDown'; cannot be applied to async Task or [UnityTest] methods
{
    public TestCommand Wrap(TestCommand command)
    {
        return new LogCommand(command, "setup");
    }
}
```

## Good

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using UnityEngine;
using UnityEngine.TestTools;

// Synchronous hooks: ITestAction runs immediately around the test body.
public class LogAroundTestAttribute : NUnitAttribute, ITestAction
{
    public void BeforeTest(ITest test)
    {
        Debug.Log($"{test.Name}: before");
    }

    public void AfterTest(ITest test)
    {
        Debug.Log($"{test.Name}: after");
    }

    public ActionTargets Targets => ActionTargets.Test;
}

// Hooks that need to yield: IOuterUnityTestAction runs before [UnitySetUp] and after [UnityTearDown].
public class WaitOneFrameAroundTestAttribute : NUnitAttribute, IOuterUnityTestAction
{
    public IEnumerator BeforeTest(ITest test)
    {
        yield return null;
    }

    public IEnumerator AfterTest(ITest test)
    {
        yield return null;
    }
}

public class MyTest
{
    [Test]
    [LogAroundTest]
    [WaitOneFrameAroundTest]
    public void SyncTest()
    {
    }

    [Test]
    [LogAroundTest]
    [WaitOneFrameAroundTest]
    public async Task AsyncTest()
    {
        await Task.Yield();
    }

    [UnityTest]
    [LogAroundTest]
    [WaitOneFrameAroundTest]
    public IEnumerator CoroutineTest()
    {
        yield return null;
    }
}
```

## Notes

- The rule inspects the base list of every class declaration in the compilation and reports each entry whose type is `NUnit.Framework.Interfaces.IWrapTestMethod`, `NUnit.Framework.Interfaces.IWrapSetUpTearDown`, or an interface derived from either. The containing type does not have to be an attribute. A class that lists only `NUnit.Framework.Interfaces.ICommandWrapper` is not reported: Unity Test Framework and NUnit read wrapper attributes through `IWrapTestMethod` and `IWrapSetUpTearDown`, so such a class is inert.
- A class derived from a class that implements one of the interfaces is not reported unless it names the interface in its own base list. The base class is reported instead. Interface declarations that derive from the interfaces are not reported; the class that names the derived interface is.
- For a partial class, the entry is reported in the declaration that names the interface.
- Only class declarations are inspected. Record and struct declarations are not, because an attribute must be a class. A generic class is inspected like any other class.
- `{0}` is the unqualified name of the interface even when the base list writes it with a namespace qualifier, and the diagnostic then covers the whole qualified name.
- The following types are exempt by exact type name; a class derived from one of them is reported only when it names the interface in its own base list. They are the built-in wrappers that work on every kind of test method, and the list mirrors [UTF1005](UTF1005.md). The exemption is required for `ParametrizedIgnoreAttribute`: this package attaches the analyzer to `UnityEngine.TestRunner` through an assembly definition reference file, and Unity applies an analyzer to the assembly it is placed in as well as to the assemblies that reference it ([Analyzer scope](https://docs.unity3d.com/Manual/analyzer-scope-and-diagnostics.html)), so the attribute, which is compiled from the Unity Test Framework package source, would otherwise be reported in every project. The NUnit attributes are precompiled and are never inspected in Unity; they are listed so that the two rules agree on what a supported wrapper is.
  - `NUnit.Framework.RepeatAttribute`
  - `NUnit.Framework.RetryAttribute`
  - `NUnit.Framework.MaxTimeAttribute`
  - `UnityEngine.TestTools.ParametrizedIgnoreAttribute`
- UTF1005 reports the usage site (a wrapper attribute applied to an `async Task` or coroutine-style test method); this rule reports the definition site. Both can be reported in one compilation.
- Tests that carry an `IOuterUnityTestAction` attribute on the test method are excluded from synchronous runs: `SynchronousFilter.Match` returns false for them, so they are skipped under the `-runSynchronously` command line option and `ExecutionSettings.runSynchronously` in the Editor API, in the same way as `[UnityTest]` methods and fixtures with a `[UnitySetUp]` or `[UnityTearDown]` method. `SynchronousFilter` does not check `ITestAction`, so a test with an `ITestAction` attribute is not excluded, and neither is a synchronous test method with a wrapper attribute. Use `ITestAction`, or keep the wrapper and suppress this rule, if synchronous runs of that test are required.
- The diagnostic is reported at the base list entry that names the interface.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF5002.severity = suggestion
```
