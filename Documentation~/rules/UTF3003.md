# UTF3003 — Suppress CA1001 (Types that own disposable fields should be disposable) on test fixtures with a UnityTearDown or UnityOneTimeTearDown method

Suppresses CA1001 ("Types that own disposable fields should be disposable") reported by Microsoft.CodeAnalysis.NetAnalyzers on a class that declares a method marked with `UnityTearDownAttribute` or `UnityOneTimeTearDownAttribute`. It is the counterpart of NUnit3004 in NUnit.Analyzers, which suppresses the same diagnostic on classes it recognizes as NUnit test fixtures.

| Item       | Value      |
|------------|------------|
| Category   | Suppressor |
| Enabled    | True       |
| Suppresses | CA1001     |
| CodeFix    | False      |

Justification: "Field should be Disposed in UnityTearDown or UnityOneTimeTearDown method."

A suppressor has no severity and no message; it is a `DiagnosticSuppressor` with a `SuppressionDescriptor` (Id, SuppressedDiagnosticId, Justification). The severity guidance for analyzers does not apply.

> [!NOTE]\
> `UnityOneTimeTearDownAttribute` is available only in Unity Test Framework 1.5.0 or later.
> Since Unity Test Framework 1.4.6, the package is a core package bundled with the Unity Editor and cannot be upgraded independently; 1.5.0 is bundled with Unity 6000.0.44f1 or later.

## Motivation

CA1001 reports a class that declares an instance field of an `IDisposable` type without implementing `IDisposable` itself, and asks the class to implement `IDisposable`. In a test fixture, the disposable members are created in a setup method and released in a teardown method; implementing `IDisposable` on the fixture is the wrong tool. NUnit invokes `Dispose` on a fixture instance at most once, after the one-time teardown (`OneTimeTearDownCommand` in the NUnit shipped with Unity Test Framework disposes the fixture when it implements `IDisposable`), so a member created in `[SetUp]` or `[UnitySetUp]` before every test would be released only for the last test. `[TearDown]` and `[UnityTearDown]` run after every test and are the right place.

NUnit.Analyzers solves this for fixtures it recognizes: NUnit3004 (`TypesThatOwnDisposableFieldsShouldBeDisposableSuppressor`) suppresses CA1001 on every class for which `IsTestFixture` holds, that is, a class declaring a method whose attribute derives from `ITestBuilder` or `ISimpleTestBuilder`, or a method marked with NUnit's `SetUpAttribute`, `TearDownAttribute`, `OneTimeSetUpAttribute`, or `OneTimeTearDownAttribute` (verified in NUnit.Analyzers 3.9.0). It does not inspect the teardown methods; it relies on NUnit1032 to check that the members are disposed there. `UnityTestAttribute` implements `ISimpleTestBuilder`, so a class with `[UnityTest]` methods is recognized. A class whose only test-related methods are marked with `UnitySetUpAttribute`, `UnityTearDownAttribute`, `UnityOneTimeSetUpAttribute`, or `UnityOneTimeTearDownAttribute` is not: those attributes derive from `NUnitAttribute`, not from the NUnit setup and teardown attributes, and the exact-type check never matches them. The typical case is a base class that loads a scene in `[UnitySetUp]`, holds the disposable objects the derived fixtures share, and releases them in `[UnityTearDown]`, while the test methods live in the derived classes.

The [Unity Test Framework manual](https://docs.unity3d.com/Manual/test-framework/reference-unitysetup-and-unityteardown.html) describes `[UnitySetUp]` and `[UnityTearDown]` as "equivalent to the NUnit `[SetUp]` and `[TearDown]` attributes, with the exception that they allow for yielding instructions for the Unity Editor", and `[UnityOneTimeSetUp]` and `[UnityOneTimeTearDown]` likewise as equivalent to `[OneTimeSetUp]` and `[OneTimeTearDown]`. A member released in a `[UnityTearDown]` method is released after every test as reliably as one released in a `[TearDown]` method, so CA1001 is noise there for the same reason NUnit3004 treats it as noise.

Without this suppressor, such a class has to implement `IDisposable` it does not need, or disable CA1001 by hand.

## Suppressed

```csharp
using System.Collections;
using System.IO;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest   // CA1001 reported by Microsoft.CodeAnalysis.NetAnalyzers, suppressed by UTF3003
{
    private StreamWriter _writer;

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
        _writer = new StreamWriter("log.txt");
    }

    [UnityTearDown]
    public IEnumerator TearDown()
    {
        _writer.Dispose();
        yield return null;
    }
}
```

## What CA1001 asks for instead

Implementing `IDisposable` compiles, but `Dispose` is invoked once after the one-time teardown, so the writer created before every test is released only for the last test:

```csharp
using System;
using System.Collections;
using System.IO;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest : IDisposable
{
    private StreamWriter _writer;

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
        _writer = new StreamWriter("log.txt");
    }

    public void Dispose()
    {
        _writer.Dispose();   // Runs once per fixture, not after every test
    }
}
```

## Not suppressed

The class has no `[UnityTearDown]` or `[UnityOneTimeTearDown]` method, so there is no teardown method to release the member in:

```csharp
using System.Collections;
using System.IO;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest   // CA1001 reported by Microsoft.CodeAnalysis.NetAnalyzers, not suppressed
{
    private StreamWriter _writer;

    [UnitySetUp]
    public IEnumerator SetUp()
    {
        yield return null;
        _writer = new StreamWriter("log.txt");
    }
}
```

## Notes

- The suppression is conditional: when reporting suppressions, the suppressor looks up `UnityEngine.TestTools.UnityTearDownAttribute` and `UnityEngine.TestTools.UnityOneTimeTearDownAttribute` independently and returns without suppressing only when neither exists in the compilation. Requiring both would silently disable the suppressor on Unity Test Framework 1.4.x, where `UnityOneTimeTearDownAttribute` does not exist. Attributes are matched by symbol, not by name, so a user-defined attribute named `UnityTearDownAttribute` in another namespace does not count.
- A CA1001 report is suppressed when the reported class declares a method marked with either attribute (on the method itself or on a method it overrides). Like NUnit3004, the suppressor does not check that the teardown method disposes the reported field; that is a separate concern, and NUnit1032 covers it for NUnit's teardown attributes only.
- Only CA1001 reports whose location resolves to a class declaration are handled, which is where Microsoft.CodeAnalysis.NetAnalyzers reports it.
- NUnit3004 excludes fixtures marked with `[FixtureLifeCycle(LifeCycle.InstancePerTestCase)]`, whose instances are created per test and should implement `IDisposable`. This suppressor has no such exclusion: `FixtureLifeCycleAttribute` was added in NUnit 3.13 and does not exist in the NUnit shipped with Unity Test Framework (`com.unity.ext.nunit` 2.0.5, based on NUnit 3.5).
- Classes NUnit3004 already recognizes are suppressed by both suppressors when NUnit.Analyzers is installed. This suppressor does not replace NUnit3004 when NUnit.Analyzers is not installed: a class whose only test-related methods carry `[Test]` or `[UnityTest]` is left to NUnit3004.
- CA1001 is reported only when Microsoft.CodeAnalysis.NetAnalyzers is installed in the project as a Roslyn analyzer and CA1001 is enabled (it is disabled by default in .NET 10), so the suppressor has no effect otherwise.
- `SuppressionDescriptor` is not tracked by `AnalyzerReleases.Unshipped.md` (RS2000/RS2008 cover `DiagnosticDescriptor` only), so no row is added there.
- Verified against NUnit.Analyzers 3.9.0, Microsoft.CodeAnalysis.NetAnalyzers 10.0.201, Unity Test Framework 1.6.0 (`UnityTearDownAttribute` and `UnityOneTimeTearDownAttribute` derive from `NUnitAttribute`), and `com.unity.ext.nunit` 2.0.5.
- The test does not run the real Microsoft.CodeAnalysis.NetAnalyzers; a test-only stub reports CA1001 at each class declaring an `IDisposable` field instead, as `NUnit2045StubAnalyzer` does for UTF3001. `UnityTearDownAttribute` and `UnityOneTimeTearDownAttribute` dummies are added next to the existing `UnitySetUpAttribute` and `UnityOneTimeSetUpAttribute` dummies.
- The "neither attribute exists in the compilation" case is not tested: the test harness compiles every dummy into each fixture, so the attribute types are always present.

To see CA1001 again, disable the suppressor. Unlike analyzers, a suppressor cannot be disabled from `.editorconfig` or `.globalconfig`: Roslyn checks only `CompilationOptions.SpecificDiagnosticOptions`, which is populated from ruleset files and the `-nowarn` compiler switch (see [dotnet/roslyn#49727](https://github.com/dotnet/roslyn/issues/49727)). In Unity, add the switch to `csc.rsp`:

```
-nowarn:UTF3003
```

or add the rule to a ruleset file (`Default.ruleset` in `Assets/`, or `<assembly name>.ruleset` next to the `.asmdef`):

```xml
<Rules AnalyzerId="UTF.Analyzers" RuleNamespace="UTF.Analyzers">
  <Rule Id="UTF3003" Action="None" />
</Rules>
```
