# UTF1008 — Only IEnumerator is supported as the return type of methods with the UnityTest attribute

Detects a method marked with `UnityTestAttribute` whose return type is not `System.Collections.IEnumerator`, such as `IEnumerator<T>`, `IEnumerable`, `Task`, or `void`. Unity Test Framework marks such a test as not runnable, so it fails without running.

| Item     | Value     |
|----------|-----------|
| Category | Structure |
| Enabled  | True      |
| Severity | Error     |
| CodeFix  | False     |

Message: "'{0}' is not supported as the return type of a UnityTest method: the test never runs. Return 'IEnumerator' instead."

`{0}` is the declared return type, e.g. `IEnumerator<object>`.

Severity is Error because the test cannot run: Unity Test Framework marks the method as not runnable when it is loaded, so the test fails without exercising any of the code under test.

## Motivation

`UnityTestAttribute` implements `IApplyToTest`, and its `ApplyToTest` method checks the return type of the test method. When the return type is not `IEnumerator`, it sets the test's `RunState` to `NotRunnable` with the skip reason "Method marked with UnityTest must return IEnumerator." The test body never runs, and the Test Runner reports the test as failed. The check runs when the test runner loads the test, so the mistake surfaces only when the test is run, not at compile time. Verified against the source of Unity Test Framework 1.4.6 and 1.6.0.

The check compares types for equality (`method.ReturnType.IsType(typeof(IEnumerator))`, where NUnit's `TypeWrapper.IsType` is `Type == type`), not for assignability. `IEnumerator<T>` implements `IEnumerator`, and an iterator method can return any of `IEnumerator`, `IEnumerator<T>`, `IEnumerable`, or `IEnumerable<T>`, so these compile without a warning and look correct. Unity Test Framework rejects all of them except `IEnumerator`.

An `async Task` method with `[UnityTest]` is rejected the same way. Apply `[Test]`, not `[UnityTest]`, to an `async Task` test method (see [UTF4006](UTF4006.md)).

### Why NUnit.Analyzers cannot be used instead

NUnit.Analyzers checks the return type of a test method in `TestMethodUsageAnalyzer` only for methods marked with NUnit's `TestCaseAttribute`, or with `TestAttribute` when no attribute implementing `ITestBuilder` is present. `UnityTestAttribute` is neither. It implements `ISimpleTestBuilder`, and for such an attribute the analyzer reports only NUnit1027 (a simple test method has parameters without data sources) and never looks at the return type. `UnityTestAttribute` also implements `ITestBuilder`, so a method marked with both `[Test]` and `[UnityTest]` skips the return-type check of `[Test]` as well. Verified by reading the source of NUnit.Analyzers 3.9.0.

## Bad

```csharp
using System.Collections;
using System.Collections.Generic;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnityTest]
    public IEnumerator<object> GenericEnumerator()   // UTF1008; not runnable, fails at load time
    {
        yield return null;
    }

    [UnityTest]
    public IEnumerable Enumerable()   // UTF1008; not runnable, fails at load time
    {
        yield return null;
    }

    [UnityTest]
    public async Task AsyncTask()   // UTF1008; not runnable, fails at load time
    {
        await Task.Yield();
    }

    [UnityTest]
    public void Void()   // UTF1008; not runnable, fails at load time
    {
        Assert.That(true, Is.True);
    }
}
```

## Good

```csharp
using System.Collections;
using System.Threading.Tasks;
using NUnit.Framework;
using UnityEngine.TestTools;

public class MyTest
{
    [UnityTest]
    public IEnumerator Coroutine()
    {
        yield return null;
    }

    [Test]
    public async Task AsyncTask()   // Apply [Test] to an async Task test method
    {
        await Task.Yield();
    }

    [Test]
    public void Void()
    {
        Assert.That(true, Is.True);
    }
}
```

## Notes

- The rule matches any method marked with `UnityTestAttribute` whose return type is not exactly `System.Collections.IEnumerator`, the same condition that Unity Test Framework uses. The diagnostic is reported once per method, at the return type.
- Only `UnityTestAttribute` itself is matched; attributes derived from it are not detected.
- Other attributes applied to the method, such as `[Test]` or `[TestCase]`, do not affect the diagnostic. An `async Task` method marked with both `[Test]` and `[UnityTest]` is reported by this rule, not by UTF1006, which does not inspect `[UnityTest]`.
- `TestCaseAttribute` and `TestCaseSourceAttribute` on a method that returns `IEnumerator` are out of scope; UTF1001 reports them.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF1008.severity = warning
```
