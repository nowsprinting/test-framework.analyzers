# UTF5003 — Attributes implementing IOuterUnityTestAction must restrict their targets with AttributeUsage

Detects an attribute class that implements `UnityEngine.TestTools.IOuterUnityTestAction` (directly, through a derived interface, or through a base class) and whose effective `[AttributeUsage]` allows a target other than `AttributeTargets.Method`. Unity Test Framework reads `IOuterUnityTestAction` from the test method only. Without the restriction, the compiler accepts the attribute on a fixture class or an assembly, and the action is silently skipped there.

| Item     | Value      |
|----------|------------|
| Category | Extensions |
| Enabled  | True       |
| Severity | Warning    |
| CodeFix  | False      |

Message: "Attributes implementing IOuterUnityTestAction are read only from test methods; applied to other targets, the action is silently skipped. Restrict the targets to AttributeTargets.Method with AttributeUsage."

Severity is Warning because the attribute works on test methods and nothing fails in the assembly that defines it. The defect surfaces at a usage site on another target, where no diagnostic and no run-time error tell the author that the action did not run. A Warning at the definition prompts the author to add the `[AttributeUsage]` that makes the compiler reject such usages (CS0592) before they spread.

> [!IMPORTANT]\
> Unity Test Framework 1.5.0 changes `GetTestActions` to walk the parent suites of the test as well (changelog entry UTF-582: "ITestAction and IOuterUnityTestAction was not triggering correctly when defined on a fixture level"), so on 1.5.0 and later a fixture-level attribute runs before every test of the fixture. `SynchronousFilter` is unchanged and still reads the test method only. The analyzer diagnoses against the 1.4.6 baseline, where the attribute is not collected from the class; no version collects it from the assembly. If every project that consumes the attribute uses 1.5.0 or later, suppress the rule for that attribute to allow `AttributeTargets.Class`.

## Motivation

`IOuterUnityTestAction` is read by `OuterUnityTestActionCommand` through `BeforeAfterTestCommandBase.GetTestActions`, which enumerates the custom attributes of the test method only (verified against Unity Test Framework 1.4.6 source). An attribute applied to the fixture class or to the assembly is never collected. `SynchronousFilter.Match`, which excludes tests that must yield from `-runSynchronously` runs, also reads `IOuterUnityTestAction` from the test method only. The [OuterUnityTestAction](https://docs.unity3d.com/Manual/test-framework/reference-outerunitytestaction.html) page describes the interface as a hook for "any tests with this attribute", and every example applies it to a test method. The interface declares only `BeforeTest` and `AfterTest`; unlike `NUnit.Framework.ITestAction`, it has no `Targets` property to choose a suite-level scope.

`NUnit.Framework.NUnitAttribute`, the base class the documentation prescribes, declares no `[AttributeUsage]`, so an attribute derived from it is valid on every target (`AttributeTargets.All`). The compiler accepts `[MyOuterAction]` on a fixture class and `[assembly: MyOuterAction]`, the tests run, and the action never runs. The mistake is silent: no diagnostic, no run-time error, and the test passes without the set-up the author expected. Declaring `[AttributeUsage(AttributeTargets.Method)]` turns the mistake into compile error CS0592 ("Attribute 'X' is not valid on this declaration type") at the usage site.

### Why existing analyzers cannot be used instead

The .NET analyzer CA1018 ("Mark attributes with AttributeUsageAttribute") reports an attribute class that has no `[AttributeUsage]`. It only checks presence, not the targets, and it skips abstract classes and every class whose base type is not exactly `System.Attribute` (verified against `MarkAttributesWithAttributeUsage.cs` in dotnet/sdk; the rule is enabled as a suggestion). An attribute derived from `NUnitAttribute` is never reported by CA1018.

NUnit.Analyzers has no rule that inspects implementations of `IOuterUnityTestAction`. Verified with NUnit.Analyzers 3.9.0.

## Bad

```csharp
using System;
using System.Collections;
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using UnityEngine.TestTools;

// No AttributeUsage: valid on every target, but read only from test methods
public class WaitOneFrameAroundTestAttribute : NUnitAttribute, IOuterUnityTestAction   // UTF5003 at 'IOuterUnityTestAction'
{
    public IEnumerator BeforeTest(ITest test)
    {
        yield return null;
    }

    public IEnumerator AfterTest(ITest test)
    {
        yield return null;
    }
}

// AttributeUsage allows Class: read only from test methods
[AttributeUsage(AttributeTargets.Method | AttributeTargets.Class)]
public class WaitOneFrameAroundTestOrFixtureAttribute : NUnitAttribute, IOuterUnityTestAction   // UTF5003 at 'IOuterUnityTestAction'
{
    public IEnumerator BeforeTest(ITest test)
    {
        yield return null;
    }

    public IEnumerator AfterTest(ITest test)
    {
        yield return null;
    }
}

[WaitOneFrameAroundTest]   // Compiles, but BeforeTest and AfterTest never run
public class MyTest
{
    [Test]
    public void SyncTest()
    {
    }
}
```

## Good

```csharp
using System;
using System.Collections;
using NUnit.Framework;
using NUnit.Framework.Interfaces;
using UnityEngine.TestTools;

[AttributeUsage(AttributeTargets.Method)]
public class WaitOneFrameAroundTestAttribute : NUnitAttribute, IOuterUnityTestAction
{
    public IEnumerator BeforeTest(ITest test)
    {
        yield return null;
    }

    public IEnumerator AfterTest(ITest test)
    {
        yield return null;
    }
}

public class MyTest
{
    [Test]
    [WaitOneFrameAroundTest]
    public void SyncTest()
    {
    }
}
```

## Notes

- The rule inspects every class declaration in the compilation that derives from `System.Attribute` (at any depth) and implements `UnityEngine.TestTools.IOuterUnityTestAction` or an interface derived from it, and reports the class when the effective `AttributeUsage` allows a target other than `AttributeTargets.Method`. A class that implements the interface but does not derive from `System.Attribute` is not reported: it cannot be applied anywhere.
- The diagnostic is reported at the base list entry that names the interface. When the class inherits the interface from a base class and its own base list does not name it, the diagnostic is reported at the class name. An abstract base class in the compilation and the classes derived from it are each reported; restricting the base class fixes all of them, because the derived classes inherit its `[AttributeUsage]`.
- The effective `AttributeUsage` follows the compiler: the `[AttributeUsage]` applied to the class itself, else the one applied to the nearest base class that has one, else `AttributeTargets.All`. Roslyn exposes no public API for this lookup, so the analyzer walks `BaseType` until it finds an `AttributeUsageAttribute` or reaches `System.Attribute`. Only `ValidOn` is inspected; `AllowMultiple` and `Inherited` are not.
- Interface declarations that derive from the interface are not reported; the classes that implement the derived interface are.
- For a partial class, the diagnostic is reported in the declaration that names the interface, or in the first declaration when no declaration names it. `[AttributeUsage]` is looked up across all declarations of the class.
- Only class declarations are inspected. Record and struct declarations are not, because an attribute must be a class. A generic class is inspected like any other class.
- The diagnostic covers the whole base list entry even when it is written with a namespace qualifier.
- A class that also implements `NUnit.Framework.ITestAction` is reported by [UTF5004](UTF5004.md) as well; the two rules agree only on `AttributeTargets.Method`, so such a class must be restricted to methods.
- `UnityEngine.TestTools.IOuterUnityTestAction` is defined in `UnityEngine.TestRunner`; the rule does nothing in a compilation that does not reference it.

To change the severity, add the following to `.editorconfig` or `.globalconfig`:

```editorconfig
dotnet_diagnostic.UTF5003.severity = suggestion
```
